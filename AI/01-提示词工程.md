## 2. 大模型接入准备

### 2.1 两种接入路线

| 路线 | 平台/工具 | 特点 |
| --- | --- | --- |
| 云端大模型 | 阿里云百炼平台 | 满参数模型、有免费额度，课程主线 |
| 本地大模型 | Ollama | 在自己电脑上部署运行，算力由本机提供，作为备用方案 |

云端接入的基本步骤（PPT 第 3–6 页）：

1. 进入阿里云百炼大模型平台，完成注册、登录和实名认证。
2. 创建 API-KEY。
3. 安装 OpenAI SDK：`pip install openai`。
4. 复制平台提供的示例代码并执行，按需替换模型名称。

### 2.2 用环境变量保护 API-KEY

不要把 API-KEY 明文写在代码里。课程使用两个环境变量：

| 环境变量 | 用途 |
| --- | --- |
| `OPENAI_API_KEY` | 供 `openai` 库读取 |
| `DASHSCOPE_API_KEY` | 供后续 LangChain 库读取 |

Windows 通过图形界面配置环境变量；macOS 在 `~/.zshrc` 中追加：

```bash
export OPENAI_API_KEY=xxx
export DASHSCOPE_API_KEY=xxx
```

配置完成后重启 PyCharm 生效；仍不生效时可重启电脑。代码侧可配合 `python-dotenv` 的 `load_dotenv()` 读取 `.env` 文件，避免密钥进入版本库。

### 2.3 Ollama 本地部署

Ollama 是简化大模型本地部署和运行的开源软件，可理解为“本地版的百炼平台”。

- 官网：<https://ollama.com>
- 模型库：<https://ollama.com/library>，提供 `deepseek-r1`、`qwen` 等模型。
- 安装：官网下载客户端，安装后执行 `ollama run 模型名称`。
- 常用命令：

```bash
ollama list          # 列出已下载模型
ollama pull 模型名   # 联网下载指定模型
ollama run 模型名    # 运行模型；不存在时先下载
ollama --help        # 查看其他命令
```

参数量选择（PPT 第 22 页的经验值）：

| 硬件 | 建议参数量 |
| --- | --- |
| 集显 | 1.5b 左右 |
| 4G 独显 | 8b 以内 |
| 8G 独显 | 14b 以内 |

参数量越大，对硬件要求越高；硬件不足时，运算和吐字速度会下降。蒸馏模型可以理解为“学习标准大模型核心本领并瘦身”的模型，参数量越大，通常学得越扎实。

### 2.4 用 OpenAI SDK 调用 Ollama

沿用 OpenAI SDK，只改两个地方：

```python
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:11434/v1",  # Ollama 的 OpenAI 兼容地址
)

completion = client.chat.completions.create(
    model="qwen3:4b",  # 换成已下载的本地模型
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "你是谁，能做什么？"},
    ],
    stream=True,
)

for chunk in completion:
    print(chunk.choices[0].delta.content, end="", flush=True)
```

## 3. OpenAI SDK 基础

### 3.1 三个核心动作

| 动作 | 代码 | 说明 |
| --- | --- | --- |
| 获取客户端 | `OpenAI(base_url=..., api_key=...)` | `base_url` 决定模型服务商，`api_key` 是密钥 |
| 调用模型 | `client.chat.completions.create(...)` | 核心参数是 `model` 和 `messages` |
| 处理结果 | `response.choices[0].message.content` | 取出模型回答文本 |

完整示例（PPT 第 32 页）：

```python
from openai import OpenAI
from openai.types.chat.chat_completion import ChatCompletion

client: OpenAI = OpenAI(
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1"
)

response: ChatCompletion = client.chat.completions.create(
    model="qwen3-max",
    messages=[
        {"role": "system", "content": "你是一个Python编程专家。"},
        {"role": "assistant", "content": "我是一个Python编程专家。请问有什么可以帮助您的吗？"},
        {"role": "user", "content": "for循环输出1到5的数字"},
    ],
)

print(response.choices[0].message.content)
```

### 3.2 三种角色

| 角色 | 定位 | 示例 |
| --- | --- | --- |
| `system` | 设定助手的整体行为、角色和规则，是全局背景设定 | “你是一个Python编程专家。” |
| `assistant` | 代表 AI 的回答，可由开发者在历史消息中预先设定 | “我是一个Python编程专家。” |
| `user` | 代表用户的问题、指令或需求 | “for循环输出1到5的数字” |

`messages` 是 list，每个元素是包含 `role` 和 `content` 的字典。把历史消息按顺序放入 `messages`，模型就能获得对话上下文。

### 3.3 流式输出

开启流式输出只需两步：`stream=True`，然后遍历响应对象：

```python
response = client.chat.completions.create(
    model="qwen3-max",
    messages=[...],
    stream=True,  # 开启流式输出
)

for chunk in response:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end="", flush=True)
```

### 3.4 响应对象结构

![OpenAI SDK ChatCompletion 响应对象结构](file:///D:/Java/data/AI/01-提示词工程/slide-031-img-02.png)

图 1-1 ChatCompletion 响应对象的关键字段（PPT 第 31 页）

一次非流式调用的响应包含：

- `id`：请求唯一标识。
- `object`：固定为 `chat.completion`。
- `created`：创建时间戳。
- `model`：本次使用的模型。
- `choices`：生成结果数组；`choices[0].message.content` 是回答文本，`finish_reason` 可能是 `stop`（正常结束）、`length`（长度超限）或 `function_call`（触发函数调用）。
- `usage`：Token 统计，含 `prompt_tokens`、`completion_tokens`、`total_tokens`。

## 4. 大模型基础

### 4.1 语言模型与 LLM

- 语言模型（LM）建模词汇序列的生成概率，即计算一个句子序列 `S = {W1, W2, ..., Wn}` 出现的概率 `P(S)`。
- 大语言模型（LLM，Large Language Model）是旨在理解和生成人类语言的 AI 模型，可处理文本分类、问答、翻译、对话等任务。
- 语言模型技术发展四阶段：基于规则和统计的语言模型 → 神经语言模型 → 预训练语言模型 → 大语言模型。

![大型语言模型简史](file:///D:/Java/data/AI/01-提示词工程/slide-042-img-01.png)

图 1-2 大型语言模型简史：2017 年 Transformer、2018 年 GPT/BERT、2019 年 GPT-2/T5、2020 年 GPT-3、2022 年 ChatGPT、2023 年 LLaMA/GPT-4、2024–2025 年 GPT-4o/LLaMA-3.1/DeepSeek-V3/R1（PPT 第 42 页）

### 4.2 LLM 的三类架构

| 类别 | 特点 | 代表模型 | 适用任务 |
| --- | --- | --- | --- |
| 自编码模型（AE，Encoder-Only） | 随机 MASK 一部分词，根据上下文预测，双向理解 | BERT | NLU：情感分析、提取式问答 |
| 自回归模型（AR，Decoder-Only） | 从左往右学习，用上文预测下一个 token，生成能力强 | GPT | NLG：摘要、翻译、抽象问答 |
| 序列到序列模型（Encoder-Decoder） | 编码器理解输入，解码器生成输出，把任务视为序列转换 | T5 | 机器翻译、文本到文本/图像等多模态任务 |

## 5. 提示词工程

### 5.1 定义

提示工程（Prompt Engineering），也称 In-Context Prompting，是在不更新模型权重的情况下，通过与大模型交互来引导其行为、获得所需结果的方法。Prompt 就是用户给大模型发出的指令。

核心观点：任何技巧都不如“清晰表达你的需求”。好的提示词甚至能让基础模型的输出效果接近简单微调后的模型。

### 5.2 六类常用技巧

| 技巧 | 做法 | 示例 |
| --- | --- | --- |
| 1. 详细描述 | 把目标、风格、字数等要求说清楚 | “用温柔的话语写一封情书，表达仰慕和思念，不少于 500 字” |
| 2. 设定角色 | 让模型充当某个角色 | “你充当 AI 算法面试官，一次问一道常考面试题，我回答后再问下一道” |
| 3. 使用分隔符 | 用中括号、XML 标签、三引号划分不同文本 | `用20个字符总结由三引号分割的文本。"""在此插入文本"""` |
| 4. 指定步骤 | 把可拆分的任务拆成明确步骤 | 步骤 1 总结并加前缀 Summary；步骤 2 翻译成英语并加前缀“翻译：” |
| 5. 提供例子 | 类似 Few-shot，让模型仿照示例输出 | “按照这句评论文本的格式，帮我创造新的样本” |
| 6. 提供参考文本 | 让模型基于给定资料回答，降低幻觉 | “根据三重引号中的文章回答；找不到答案就写‘我找不到答案’，不要自己造答案” |

### 5.3 Zero-shot 与 Few-shot

| 视角 | Zero-shot | Few-shot |
| --- | --- | --- |
| 模型训练 | 训练时没见过测试类别，依靠已学属性/语义关联迁移到新类别 | 学习大量类别后，只需少量样本即可快速泛化；一个样本叫 one-shot |
| 提示词优化 | 不提供示例，仅用语言描述任务、目标、约束，依赖预训练知识 | 提供少量示例，让模型对齐示例的格式和回答方式 |

Zero-shot 提示示例：

```text
请判断""包围的用户评论中的情感倾向，输出 正面 或 负面。
"这款代餐鸡胸肉饱腹感很强，吃起来也不柴，很推荐！"
```

Few-shot 提示示例：

```text
请抽取产品名称和核心卖点2个字段，格式为Json，我提供2个示例。
示例1：MacBookPro高效节能，性能强大，适合牛马工作使用
输出：{"产品名称": "MacBookPro", "产品卖点": "高效节能，性能强大"}
示例2：联想笔记本拥有RTX4060独立显卡，畅玩游戏，丝滑流畅
输出：{"产品名称": "联想笔记本", "产品卖点": "畅玩游戏，丝滑流畅"}
请处理：华为MatepadPro，高清大屏，长效续航，你的好帮手。
```

## 6. 实战一：金融文本分类

### 6.1 任务

把 4 段金融文本分到 `['新闻报道', '公司公告', '财务公告', '分析师报告']` 四类；不属于四类的输出“不清楚类型”。

Prompt 设计考虑两点：

1. 向模型解释什么是“文本分类任务”。
2. 让模型按指定格式输出。

采用 Few-shot：把“示例文本 + 正确类别”作为历史消息加入 `messages`。

### 6.2 代码

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1"
)

examples_data = {
    '新闻报道': '今日，股市经历了一轮震荡，受到宏观经济数据和全球贸易紧张局势的影响。投资者密切关注美联储可能的政策调整，以适应市场的不确定性。',
    '财务报告': '本公司年度财务报告显示，去年公司实现了稳步增长的盈利，同时资产负债表呈现强劲的状况。经济环境的稳定和管理层的有效战略执行为公司的健康发展奠定了基础。',
    '公司公告': '本公司高兴地宣布成功完成最新一轮并购交易，收购了一家在人工智能领域领先的公司。这一战略举措将有助于扩大我们的业务领域，提高市场竞争力',
    '分析师报告': '最新的行业分析报告指出，科技公司的创新将成为未来增长的主要推动力。云计算、人工智能和数字化转型被认为是引领行业发展的关键因素，投资者应关注这些趋势',
}

examples_types = ['新闻报道', '财务报道', '公司公告', '分析师报告']

questions = [
    "今日，央行发布公告宣布降低利率，以刺激经济增长。这一降息举措将影响贷款利率，并在未来几个季度内对金融市场产生影响。",
    "ABC公司今日发布公告称，已成功完成对XYZ公司股权的收购交易。本次交易是ABC公司在扩大业务范围、加强市场竞争力方面的重要举措。据悉，此次收购将进一步巩固ABC公司在行业中的地位，并为未来业务发展提供更广阔的发展空间。详情请见公司官方网站公告栏",
    "公司资产负债表显示，公司偿债能力强劲，现金流充足，为未来投资和扩张提供了坚实的财务基础。",
    "最新的分析报告指出，可再生能源行业预计将在未来几年经历持续增长，投资者应该关注这一领域的投资机会",
    "小明喜欢小新哟",
]


def init_prompt(examples):
    prompt_list = [
        {
            "role": "system",
            "content": f"你是一个金融专家，需要对输入的金融领域文本进行分析，将类型归类到examples_types，不在这四类的数据，输出'不清楚类型'，以下是几个示例分类：",
        }
    ]
    for class_type, example_text in examples.items():
        prompt_list.append({"role": "user", "content": example_text})
        prompt_list.append({"role": "assistant", "content": class_type})
    return prompt_list


if __name__ == '__main__':
    messages = init_prompt(examples_data)
    for q in questions:
        response = client.chat.completions.create(
            model="qwen3-max",
            messages=messages + [{"role": "user", "content": f"请分析如下句子是什么类别：{q}"}],
            stream=False,
        )
        print(response.choices[0].message.content)
```

> 注意：PPT 原代码在 system 提示中直接写了字符串 `examples_types`，并没有把列表插值进去；实际使用时建议改成 `{examples_types}`，否则模型看不到四个类别的名称。

## 7. JSON 基础

JSON 是带格式的字符串，便于程序和程序之间交换数据。Python 中：

- JSON 对象 ↔ Python 字典。
- JSON 数组 ↔ Python 列表（内含多个字典）。

| 格式 | 结构化 | 抽取信息 | Schema | 空间占用 |
| --- | --- | --- | --- | --- |
| 纯 Text | 否 | 不方便 | 无 | 小 |
| CSV | 是 | 方便 | 无 Schema，有风险 | 较小 |
| JSON | 是 | 方便 | 每条数据都带 Schema | 较大 |

Python 内置 `json` 库：

```python
import json

data = {"name": "周杰轮", "age": 11, "hobby": ["唱", "跳", "rap"]}

json_str = json.dumps(data, ensure_ascii=False)  # 字典/列表 → JSON 字符串；ensure_ascii=False 保留中文
data2 = json.loads(json_str)                     # JSON 字符串 → 字典/列表
```

        }

}

        }

                'role': 'assistant',
                'content': json.dumps(example['answers']),
            })
    return history

    if '```json' in response:
        res = re.findall(r'```json(.*?)```', response)
        if len(res) and res[0]:
            response = res[0]
        response = response.replace('、', ',')
    try:
        return json.loads(response)
    except Exception:
        return response


def qwen_model(prompt, client, history=[]):
    completion = client.chat.completions.create(
        model=os.getenv("model"),
        messages=history + [{'role': 'user', 'content': prompt}],
    )
    return completion.choices[0].message.content

## 9. 实战三：金融文本匹配

任务：判断两个句子语义是否相同，输出 `是` 或 `不是`。

```python
examples = {
    '是': [
        ('公司ABC发布了季度财报，显示盈利增长。', '财报披露，公司ABC利润上升。'),
    ],
    '不是': [
        ('黄金价格下跌，投资者抛售。', '外汇市场交易额创下新高。'),
        ('央行降息，刺激经济增长。', '新能源技术的创新。'),
    ]
}

sentence_pairs = [
    ('股票市场今日大涨，投资者乐观。', '持续上涨的市场让投资者感到满意。'),
    ('油价大幅下跌，能源公司面临挑战。', '未来智能城市的建设趋势愈发明显。'),
    ('利率上升，影响房地产市场。', '高利率对房地产有一定冲击。'),
]


def init_prompt(examples):
    history = [
        {
            'role': 'system',
            'content': '判断2个句子语义是否相似，相似句子返回是，不相似句子返回不是，不要其他回答',
        }
    ]
    for label, example in examples.items():
        for sentence_pair in example:
            history.append({
                'role': 'user',
                'content': "句子一：{}\n句子二：{}\n 是否是语义相同的句子？".format(
                    sentence_pair[0], sentence_pair[1]
                ),
            })
            history.append({'role': 'assistant', 'content': label})
    return history


def qwen_model(prompt, client, history=[]):
    completion = client.chat.completions.create(
        model=os.getenv("model"),
        messages=history + [{'role': 'user', 'content': prompt}],
    )
    return completion.choices[0].message.content


if __name__ == '__main__':
    history = init_prompt(examples)
    for pairs in sentence_pairs:
        print(pairs)
        prompt = "句子一：{}\n句子二：{}\n 是否是语义相同的句子？".format(pairs[0], pairs[1])
        response = qwen_model(prompt, client, history)
        print(response)
```

## 10. 面试题与答案要点

### 10.1 什么是提示词工程？

- 在不更新模型权重的前提下，通过设计输入指令引导模型行为。
- 目标是让模型输出更准确、更符合格式要求。
- 常用手段：清晰描述、角色设定、分隔符、步骤拆解、示例、参考文本。

### 10.2 Zero-shot 和 Few-shot 的区别？

- Zero-shot：不提供示例，只描述任务，依赖模型预训练知识。
- Few-shot：提供少量示例，让模型对齐输出格式和判断标准。
- 在训练语境中，Zero-shot 指迁移到未见类别，Few-shot 指用少量样本快速泛化。

### 10.3 如何降低大模型幻觉？

- 提供参考文本，要求模型“找不到答案就说找不到”，不要自行编造。
- 使用 RAG：先检索知识库，再把检索结果和问题一起放入 Prompt。
- 对输出做校验和后处理（如 JSON 解析失败时重试或修正）。

### 10.4 如何让模型稳定输出 JSON？

- 在 system/user 提示中明确 JSON 的字段、类型和示例。
- 使用 Few-shot 给出输入输出样例。
- 解析前清理 ```json 围栏、中文标点等噪声。
- 解析失败时捕获异常，返回原始文本或触发重试。

### 10.5 流式输出怎么实现？

- OpenAI SDK：`stream=True`，遍历 `chunk`，读取 `chunk.choices[0].delta.content`。
- 输出时使用 `end=""`、`flush=True`，避免每个片段换行或缓冲。

## 11. 易错点

- API-KEY 不要硬编码；优先使用环境变量或 `.env`。
- `model` 名称要区分聊天模型和大语言模型：课程中 `qwen3-max` 是聊天模型，`qwen-max` 是大语言模型。
- `messages` 的顺序会影响上下文；历史消息要按 user/assistant 交替组织。
- 流式响应的内容在 `delta.content`，非流式在 `message.content`。
- JSON 输出可能带 Markdown 围栏或中文标点，必须后处理。
- 代码中的 `examples_types` 未插值、`response.replace` 未赋值，是 PPT 原代码的瑕疵。
- 本地 Ollama 调用要确认服务已启动，默认端口 `11434`。
