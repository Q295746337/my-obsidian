# 10-设计模式 面试笔记

> 范围：面试官怎么问设计模式、工厂模式、策略模式、责任链模式，以及项目中的落地方式。
> 本文是设计模式专题的主笔记；Spring AOP、Bean 等框架实现见 [[04-框架篇]]。

> 主笔记：[[八股文/10-设计模式与AI|八股文·设计模式与 AI]]。


## 1. 面试官怎么问

常见问法：**你之前项目中用过设计模式吗？**

**回答结构**

1. 先点名项目中真实用过的模式：工厂方法、策略、责任链。
2. 说明业务场景，而不是只背定义。
3. 说明解决了什么问题：解耦、消除 if-else、链路编排。
4. 能说出扩展点：新增类型时改哪里、不改哪里。

**易错点**

- 不要把所有 23 种模式都报一遍，挑 2–3 个能讲透的。
- 不要把框架里看过的模式说成自己项目里写过的。

## 2. 工厂模式

本节依次回答：2.1 需求示例、2.2 简单工厂、2.3 工厂方法、2.4 抽象工厂、2.5 三种工厂对比。

### 2.1 需求示例

咖啡店点餐系统：

- 咖啡类 `Coffee`，子类 `AmericanCoffee`、`LatteCoffee`。
- 咖啡店类 `CoffeeStore`，具有点咖啡的功能。

最直接的写法是根据类型 if-else 创建咖啡：

```java
public static Coffee orderCoffee(String type) {
    Coffee coffee = null;
    if ("american".equals(type)) {
        coffee = new AmericanCoffee();
    } else if ("latte".equals(type)) {
        coffee = new LatteCoffee();
    }
    coffee.addMilk();
    coffee.addSugar();
    return coffee;
}
```

问题：新增咖啡类型要修改这段代码，违反开闭原则。

### 2.2 简单工厂

角色：

- 抽象产品：定义产品规范。
- 具体产品：实现或继承抽象产品。
- 具体工厂：提供创建产品的方法。

优点：调用者不用关心创建过程。
缺点：所有产品共用一个工厂，新增产品要修改工厂代码，违反开闭原则。

> 补充：来自新下载讲义。把创建方法写成 `static` 就是静态工厂，它不属于 23 种设计模式，只是简单工厂的一种常见写法。

### 2.3 工厂方法

角色：

- 抽象工厂：提供创建产品的接口。
- 具体工厂：实现抽象工厂方法，创建具体产品。
- 抽象产品、具体产品。

![工厂方法类图](file:///D:/Java/data/面试/10-设计模式/slide007_img1.png)

> 图：CoffeeFactory 接口由 AmericanCoffeeFactory、LatteCoffeeFactory 实现，CoffeeStore 只依赖抽象工厂和抽象产品。

**优点**

- 只需知道具体工厂名称就能得到产品，不关心创建过程。
- 新增产品只需增加具体产品类和对应工厂类，符合开闭原则。

**缺点**

- 每增加一个产品就要增加一个产品类和一个工厂类，系统复杂度上升。

### 2.4 抽象工厂

- 产品族：同一品牌下的所有产品，例如华为的电脑、手机。
- 产品等级：多个品牌下的同种产品，例如华为和小米都有手机。
- 工厂方法只考虑同一等级产品；抽象工厂可以生产多个等级的产品。
- 抽象工厂是工厂方法模式的升级版，是“工厂的工厂”。

**优点**：保证客户端始终只使用同一个产品族中的对象。
**缺点**：产品族新增一个产品时，所有工厂类都要修改。

> 补充：来自新下载讲义。常见使用场景：需要创建一组相互关联的产品族（电器厂的电视、洗衣机、空调）；系统有多个产品族但每次只使用其中一族（同一品牌的衣服和鞋）；输入法换皮肤、生成不同操作系统的程序等。

### 2.5 三种工厂对比

| 模式 | 特点 | 是否符合开闭原则 | 项目使用 |
| --- | --- | --- | --- |
| 简单工厂 | 所有产品一个工厂，新增产品改代码 | 否 | 可借鉴思路 |
| 工厂方法 | 每个产品一个工厂 | 是 | 项目中用得最多 |
| 抽象工厂 | 多个产品等级配合生产 | 产品族扩展困难 | 企业开发较少 |

**一句话总结**：工厂模式的核心是解耦对象的创建和使用。

## 3. 策略模式

本节依次回答：3.1 定义、3.2 优缺点、3.3 项目案例：工厂 + 策略做登录、3.4 举一反三。

### 3.1 定义

策略模式定义一系列算法，把每个算法封装起来，使它们可以相互替换，算法的变化不会影响使用算法的客户。

**角色**

| 角色 | 作用 |
| --- | --- |
| 抽象策略 Strategy | 接口或抽象类，定义所有策略的公共方法 |
| 具体策略 Concrete Strategy | 实现具体算法 |
| 环境 Context | 持有策略引用，供客户端调用 |

![策略模式类图](file:///D:/Java/data/面试/10-设计模式/slide016_img1.png)

> 图：TravelContext 聚合 Strategy，bicycle、car、train、aircraft 实现 travel()，运行时可替换出行策略。

**例子**：旅游出行方式有自行车、汽车、火车、飞机，每种方式是一种策略。

### 3.2 优缺点

**优点**

- 策略类之间可以自由切换。
- 易于扩展。
- 避免多重条件选择语句（if-else），体现面向对象设计思想。

**缺点**

- 客户端必须知道所有策略类，并自行决定使用哪一个。
- 会产生很多策略类。

### 3.3 项目案例：工厂 + 策略做登录

业务：支持用户名密码、短信验证码、微信、QQ 等多种登录方式。

- 每种登录方式实现统一接口，由 Spring 容器管理。
- 用配置定义类型与策略的映射：

```yaml
login:
  types:
    account: accountGranter
    sms: smsGranter
    we_chat: weChatGranter
    qq: qqGranter
```

- 工厂根据参数从容器中取策略：

```java
public UserGranter getGranter(String grantType) {
    UserGranter tokenGranter = granterPool.get(grantType);
    return tokenGranter;
}
```

**扩展方式**：新增 QQ 登录只需增加策略类并加一行配置，不需要改工厂逻辑。

### 3.4 举一反三

- 订单支付策略（支付宝、微信、银行卡）。
- 解析不同类型 Excel（xls、xlsx）。
- 打折促销（满 300 打 9 折、满 500 打 8 折）。
- 物流运费阶梯计算。

**一句话总结**：只要代码中有冗长的 if-else 或 switch 分支判断，都可以考虑策略模式。

## 4. 责任链模式

本节依次回答：4.1 定义、4.2 订单处理示例、4.3 优缺点、4.4 举一反三。

### 4.1 定义

责任链模式把所有请求处理者通过“前一个对象记住下一个对象的引用”连成一条链。请求沿链传递，直到有对象处理为止。

**角色**

| 角色 | 作用 |
| --- | --- |
| 抽象处理者 Handler | 定义处理请求的接口，包含处理方法和后继连接 |
| 具体处理者 Concrete Handler | 判断能否处理，不能处理则转给后继者 |
| 客户类 Client | 创建处理链，向链头提交请求 |

![责任链类图](file:///D:/Java/data/面试/10-设计模式/slide025_img1.png)

> 图：Client 创建处理链，抽象 Handler 持有 next，订单校验、填充、算价、落库等处理器依次处理 OrderInfo。

### 4.2 订单处理示例

订单创建可以拆成一条链：

1. 校验参数。
2. 填充订单数据。
3. 算价。
4. 落库。

### 4.3 优缺点

**优点**

- 降低对象之间的耦合度。
- 增强系统可扩展性。
- 增强给对象指派职责的灵活性。
- 简化对象之间的连接，责任分担。

**缺点**

- 链较长时，请求可能经过多个处理对象，性能受影响。
- 链的合理性要靠客户端保证，配置错误可能导致循环调用。
- 请求没有明确的接收者，可能传到链尾仍得不到处理。

> 补充：来自新下载讲义。责任链的“请求可能无人处理”是设计时要特别确认的点，链尾通常要有一个兜底处理者或明确的失败返回。

### 4.4 举一反三

- 内容审核（视频、文章、课程）。
- 订单创建。
- 简易流程审批。

**一句话总结**：责任链适合把一串处理步骤解耦成可插拔的节点。

## 5. 面试速记

| 问题 | 一句话答案 |
| --- | --- |
| 项目用过什么模式 | 工厂方法、策略、责任链，结合登录、支付、订单场景 |
| 简单工厂 | 一个工厂创建所有产品，新增产品改代码 |
| 工厂方法 | 一个产品一个工厂，符合开闭原则 |
| 抽象工厂 | 生产多个产品等级，是工厂的工厂 |
| 策略模式 | 封装可互换算法，消除 if-else |
| 策略 + 工厂 | 工厂根据参数提供策略，策略由 Spring 管理 |
| 责任链 | 处理者连成链，请求沿链传递 |
| 什么时候用策略 | 多种支付、解析、优惠、运费计算 |
| 什么时候用责任链 | 参数校验、订单创建、审核、审批 |
