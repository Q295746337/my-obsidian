# 09-JVM虚拟机篇 面试笔记

> 范围：JVM 组成、程序计数器、堆、虚拟机栈、方法区、直接内存、类加载、垃圾回收、引用类型、JVM 调优与排查。
> 主笔记：[[JVM/JVM 索引|JVM]]。内存结构、GC 算法和字节码细节以主笔记为准。

## 1. JVM 由哪些部分组成

![JVM 组成结构](file:///D:/Java/data/面试/09-JVM虚拟机篇/slide005_img1.png)

> 图：源码编译为字节码后由类加载子系统加载；运行时数据区包含方法区、堆、程序计数器、虚拟机栈、本地方法栈；执行引擎包含解释器、JIT 编译器和 GC。

| 部分 | 作用 |
| --- | --- |
| 类加载子系统 | 把 .class 文件加载到 JVM |
| 运行时数据区 | 方法区、堆、程序计数器、虚拟机栈、本地方法栈 |
| 执行引擎 | 解释器、JIT 编译器、垃圾回收 |
| 本地方法接口/本地库 | 调用本地方法 |

**JVM 的好处**

- 一次编写，到处运行。
- 自动内存管理，垃圾回收机制。

## 2. 程序计数器

- 线程私有，每个线程一份。
- 内部保存正在执行的字节码指令地址（行号）。
- 用于记录当前线程执行到哪条字节码指令。

![字节码指令序列](file:///D:/Java/data/面试/09-JVM虚拟机篇/slide009_img1.png)

> 图：`javap -v` 输出的字节码指令序列，程序计数器就是记录当前执行到这些指令中的哪一条。

## 3. Java 堆

- 线程共享，主要保存对象实例、数组等。
- 堆中没有内存分配给实例且无法扩展时，抛出 OutOfMemoryError。
- 组成：年轻代 + 老年代，默认比例 1:2。

### 3.1 年轻代

- 分为 Eden、From Survivor、To Survivor。
- 默认比例 8:1:1。
- 新创建的对象先分配到 Eden。
- 经过多次回收仍存活的对象晋升到老年代，最多 15 次；幸存区内存不足或大对象会提前晋升。

### 3.2 老年代

- 保存生命周期长的对象。

### 3.3 JDK 1.7 与 1.8 的区别

| 版本 | 方法区实现 | 存储位置 |
| --- | --- | --- |
| 1.7 | 永久代 | 堆内存 |
| 1.8 | 元空间 | 本地内存 |

- 1.8 移除永久代，把类信息、静态变量、常量、编译后的代码放到本地内存的元空间，避免 OOM。

> 补充：来自新下载讲义。永久代有大小上限，加载类过多会 `OutOfMemoryError`；元空间使用本地内存，默认只受本地内存限制。JDK 7 起字符串常量池已经从永久代移到堆中，JDK 8 才用元空间替代永久代。这样调整既减少永久代 OOM，也便于 HotSpot 与 JRockit 融合。

## 4. 虚拟机栈

- 每个线程运行时所需要的内存，先进后出。
- 每个栈由多个栈帧组成，对应每次方法调用。
- 每个线程只有一个活动栈帧，对应当前正在执行的方法。
- 栈帧包含参数、局部变量、返回地址等。

### 4.1 常见追问

| 问题 | 回答 |
| --- | --- |
| 垃圾回收是否涉及栈内存 | 不涉及；栈帧弹栈后内存自动释放，GC 主要针对堆 |
| 栈内存越大越好吗 | 未必；默认约 1024k，栈帧过大导致可创建线程数变少 |
| 方法内局部变量是否线程安全 | 没有逃离方法作用范围则安全；引用对象并逃离作用范围则要考虑 |
| 什么情况栈溢出 | 栈帧过多（递归）或栈帧过大，抛 StackOverflowError |

### 4.2 堆栈区别

| 维度 | 栈 | 堆 |
| --- | --- | --- |
| 存储 | 局部变量、方法调用 | 对象、数组 |
| 回收 | 不 GC，自动释放 | GC 回收 |
| 线程 | 私有 | 共享 |
| 异常 | StackOverflowError | OutOfMemoryError |

## 5. 方法区、常量池与直接内存

本节依次回答：5.1 方法区、5.2 常量池、5.3 直接内存。

### 5.1 方法区

- 线程共享。
- 存储类信息、运行时常量池。
- 虚拟机启动时创建，关闭时释放。
- 内存不足抛 `OutOfMemoryError: Metaspace`。

### 5.2 常量池

- 常量池可以看作一张表，虚拟机指令根据它找到类名、方法名、参数类型、字面量等信息。
- 常量池在 `.class` 文件中。
- 类被加载后，常量池信息放入运行时常量池，符号地址变为真实地址。

### 5.3 直接内存

- 不属于 JVM 内存结构，不由 JVM 管理。
- 是虚拟机的系统内存，常见于 NIO 操作，用作数据缓冲区。
- 分配回收成本较高，但读写性能高，不受 JVM 内存回收管理。

## 6. 类加载器与双亲委派

本节依次回答：6.1 四种类加载器、6.2 双亲委派模型、6.3 为什么用双亲委派。

### 6.1 四种类加载器

| 加载器 | 加载范围 |
| --- | --- |
| 启动类加载器 Bootstrap | `JAVA_HOME/jre/lib` |
| 扩展类加载器 Ext | `JAVA_HOME/jre/lib/ext` |
| 应用类加载器 App | classpath 下的类 |
| 自定义类加载器 | 继承 ClassLoader，自定义加载规则 |

### 6.2 双亲委派模型

- 加载某个类时，先委托上一级加载器加载。
- 上级还有上级就继续向上委托。
- 上级没有加载到，子加载器才尝试加载。

![双亲委派模型](file:///D:/Java/data/面试/09-JVM虚拟机篇/slide040_img1.png)

> 图：CustomizeClassLoader → AppClassLoader → ExtClassLoader → Bootstrap，自底向上委派、自顶向下尝试加载。

### 6.3 为什么用双亲委派

1. 避免类重复加载，父加载器已加载则无需重复加载，保证唯一性。
2. 保证安全，防止核心类库被篡改。

**示例**：自定义 `java.lang.String`，由于双亲委派，最终由启动类加载器加载 JDK 自带的 String，自定义类不会生效。

## 7. 类装载执行过程

类从加载到卸载包括：加载、验证、准备、解析、初始化、使用、卸载。验证、准备、解析统称连接。

| 阶段 | 工作 |
| --- | --- |
| 加载 | 通过全类名获取二进制数据流；解析为方法区数据结构；创建 Class 对象作为访问入口 |
| 验证 | 文件格式、元数据、字节码、符号引用验证，保证符合 JVM 规范 |
| 准备 | 为类变量分配内存并设置初始值 |
| 解析 | 符号引用转换为直接引用 |
| 初始化 | 对静态变量、静态代码块执行初始化 |
| 使用 | 从入口方法开始执行用户代码 |
| 卸载 | 程序结束后销毁 Class 对象 |

**准备阶段的细节**

- `static` 变量在准备阶段分配空间并设默认值，赋值在初始化阶段完成。
- `static final` 基本类型和字符串常量，值已确定，准备阶段完成赋值。
- `static final` 引用类型，赋值仍在初始化阶段完成。

**易错点**

- “准备”不是执行 `static` 赋值语句，`static int b = 10` 在准备阶段 b 是 0。
- 初始化时如果父类未初始化，先初始化父类；多个静态变量和静态代码块按自上而下顺序执行。

## 8. 垃圾回收

本节依次回答：8.1 对象什么时候可回收、8.2 三种垃圾回收算法、8.3 分代回收。

### 8.1 对象什么时候可回收

如果一个或多个对象没有任何引用指向它，它就是垃圾。定位垃圾有两种方式：

| 方式 | 说明 | 问题 |
| --- | --- | --- |
| 引用计数法 | 对象被引用一次计数加一，计数为 0 可回收 | 循环引用会失效，导致内存泄漏 |
| 可达性分析 | 从 GC Root 出发沿引用链扫描，找不到则可回收 | 现代虚拟机采用 |

**GC Root 包括**

- 虚拟机栈（栈帧本地变量表）中引用的对象。
- 方法区中类静态属性引用的对象。
- 方法区中常量引用的对象。
- 本地方法栈中 JNI 引用的对象。

### 8.2 三种垃圾回收算法

| 算法 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 标记清除 | 标记垃圾后直接清除 | 速度较快 | 内存碎片化 |
| 标记整理 | 标记后把存活对象向一端移动，再清理边界外 | 无碎片 | 对象移动，效率较低 |
| 复制 | 内存分两块，存活对象复制到另一块后清空原块 | 垃圾多时效率高，无碎片 | 只能使用一半内存 |

### 8.3 分代回收

- 堆分年轻代和老年代，比例 1:2。
- 年轻代 Eden、From、To，比例 8:1:1。
- 新对象进入 Eden；Eden 满时标记 Eden 和 From 的存活对象，复制到 To，释放 Eden 和 From。
- 下一次 Eden 满时，标记 Eden 和 To 的存活对象，复制到 From。
- 熬过多次回收（最多 15 次）晋升老年代。

| GC 类型 | 范围 | 特点 |
| --- | --- | --- |
| Minor GC / Young GC | 新生代 | 暂停时间短 |
| Mixed GC | 新生代 + 老年代部分区域 | G1 特有 |
| Full GC | 新生代 + 老年代完整回收 | 暂停时间长，应尽量避免 |

## 9. 垃圾收集器

| 收集器 | 作用区域 | 算法/特点 |
| --- | --- | --- |
| Serial / Serial Old | 新生代 / 老年代 | 单线程，STW；复制 / 标记整理 |
| Parallel New / Parallel Old | 新生代 / 老年代 | 多线程，STW；JDK 8 默认 |
| CMS | 老年代 | 并发、标记清除，追求最短停顿 |
| G1 | 新生代 + 老年代 | 分区、复制算法，兼顾响应时间与吞吐量 |

### 9.1 CMS

- 全称 Concurrent Mark Sweep。
- 针对老年代，以最短回收停顿时间为目标。
- 最大特点：回收时应用仍能正常运行。

### 9.2 G1

- JDK 9 之后默认。
- 堆划分为多个区域，每个区域可充当 Eden、Survivor、Old、Humongous，Humongous 专为大对象准备。
- 采用复制算法，响应时间与吞吐量兼顾。
- 三个阶段：
  1. 新生代回收（STW）。
  2. 并发标记；重新标记阶段需要 STW，解决漏标。
  3. 混合收集：回收 Eden、Survivor 和部分 Old，优先回收价值高（存活对象少）的区域。
- 老年代占用超过阈值（默认 45%）触发并发标记。
- 并发失败（回收速度赶不上创建对象速度）会触发 Full GC。

**名称由来**：Garbage First，优先回收价值高的区域。

## 10. 四种引用

| 引用 | 回收时机 |
| --- | --- |
| 强引用 | 只要 GC Roots 能找到就不回收 |
| 软引用 | 仅软引用引用时，GC 后内存仍不足再回收 |
| 弱引用 | 仅弱引用引用时，只要 GC 就回收 |
| 虚引用 | 必须配合引用队列，对象回收时虚引用入队，由 Reference Handler 释放直接内存 |

## 11. JVM 调优与排查

本节依次回答：11.1 参数在哪里设置、11.2 常用参数、11.3 调优工具、11.4 内存泄漏排查、11.5 CPU 飙高排查。

### 11.1 参数在哪里设置

- war 包部署在 Tomcat：修改 `TOMCAT_HOME/bin/catalina.sh`。
- jar 包部署：启动参数设置。

```bash
nohup java -Xms512m -Xmx1024m -jar xxxx.jar --spring.profiles.active=prod &
```

- `nohup`：后台不挂断运行，退出终端不影响。
- `&`：后台执行。

### 11.2 常用参数

| 参数 | 作用 |
| --- | --- |
| `-Xms` | 堆初始大小 |
| `-Xmx` | 堆最大大小 |
| `-Xss` | 每个线程栈大小 |
| `-XX:SurvivorRatio=8` | Eden 与 Survivor 比例，survivor:eden = 2:8 |
| `-XX:+UseG1GC` | 使用 G1 |
| `-XX:+UseParallelGC`、`-XX:+UseParallelOldGC` | 使用并行收集器 |

**堆大小建议**

- 最大大小默认是物理内存的 1/4，初始大小是 1/64。
- 通常把 `-Xms` 和 `-Xmx` 设为相同，避免堆收缩带来额外时间。
- 堆太小会频繁 GC；堆太大会让 Full GC 扫描时间变长。

### 11.3 调优工具

| 工具 | 作用 |
| --- | --- |
| jps | 进程状态信息 |
| jstack | 线程堆栈信息 |
| jmap | 堆转储、内存使用情况 |
| jhat | 堆转储快照分析 |
| jstat | JVM 统计监测，GC、类加载、新生代统计 |
| jconsole | 基于 JMX 的 GUI 监控 |
| VisualVM | 监控线程、内存，分析 dump |

### 11.4 内存泄漏排查

1. 用 `jmap` 或 JVM 参数获取堆内存快照 dump。
2. 用 VisualVM 加载离线 dump 文件。
3. 查看堆信息，定位内存溢出大致代码位置。
4. 阅读上下文，修复代码。

```bash
jmap -dump:format=b,file=heap.hprof <pid>
```

```bash
-XX:+HeapDumpOnOutOfMemoryError
-XX:HeapDumpPath=/home/app/dumps/
```

- 内存溢出后程序可能直接中断，jmap 只能打印运行中的程序，建议用参数方式生成 dump。

![VisualVM 分析 dump](file:///D:/Java/data/面试/09-JVM虚拟机篇/slide127_img1.png)

> 图：VisualVM 打开 hprof 后显示 OutOfMemoryError 线程 main 的调用栈，可直接定位到 String 初始化附近的代码。

### 11.5 CPU 飙高排查

1. `top` 查看占用 CPU 高的进程。

![top 命令输出](file:///D:/Java/data/面试/09-JVM虚拟机篇/slide131_img1.png)

> 图：top 输出中 PID 40940 的 java 进程 CPU 占用 88.3%，先锁定进程。

2. `ps H -eo pid,tid,%cpu | grep <pid>` 查看进程内线程，找到 CPU 高的线程 id。
3. 把线程 id 转为十六进制。
4. `jstack <pid>` 查看线程堆栈，根据十六进制 id 找到问题代码行。
