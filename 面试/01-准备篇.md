# 01-准备篇 面试笔记

> 范围：简历如何被筛选、简历怎么写、练手项目怎么找、面试流程与心态。
> 本篇是方法论文档，没有对应技术主笔记；各技术专题见 [[面试 索引]]。

## 1. 简历是如何被筛选的

本节依次回答：1.1 HR 筛选、1.2 部门负责人筛选。

### 1.1 HR 筛选

- 常见渠道：Boss 直聘、智联招聘的招聘方后台按条件搜索。
- 关注硬条件：学历、院校、经验、年龄、跳槽频率。

**简历石沉大海的两类原因**

| 原因 | 说明 |
| --- | --- |
| 市场原因 | 岗位少、竞争大 |
| 简历原因 | 硬条件不匹配、关键词缺失、项目描述没有亮点 |

### 1.2 部门负责人筛选

| 维度 | 关注点 |
| --- | --- |
| 技术条件 | 是否符合当前项目技术栈 |
| 业务条件 | 是否有电商、银行、物流等业务经验 |
| 额外加分项 | 高并发高可用、公有云开发、团队管理经验 |

**回答模板**：HR 先按学历、院校、经验、年龄、跳槽频率筛；部门负责人再看技术栈、业务匹配和加分项。所以简历要针对岗位写关键词。

## 2. 简历怎么写

本节依次回答：2.1 整体结构、2.2 职业技能、2.3 项目经历、2.4 简历自查。

### 2.1 整体结构

一份完整简历包含 8 个部分：

1. 基本信息
2. 教育背景
3. 求职意向
4. 工作经历
5. 职业技能
6. 项目经历
7. 个人优势
8. 个人荣誉

**原则**：在真实的前提下适当美化；不要过于夸张，关键在难点和亮点。

### 2.2 职业技能

- 放在简历的黄金位置，是 HR 筛选的重要参考。
- 基本准则：写在简历上的必须能聊，不然就别写。
- 参考公式：职业技能 = 必要技术 + 其他技术。
- 有针对性地引导面试官，让他问你想让他问的。

| 年限 | 必要技术 | 其他技术数量 |
| --- | --- | --- |
| 1–2 年 | SpringBoot + SSM + Redis + 数据库 | 2–3 项 |
| 3–5 年 | SpringBoot + SSM + Redis + 数据库 | 3–4 项 |
| 5 年以上 | SpringBoot + SSM + Redis + 数据库 | 5 项以上 |

其他技术可选：微服务、ES、MQ、源码、高并发、JVM、技术选型、设计能力等。

### 2.3 项目经历

- 项目个数以工作经历为准；时间比较久的可以只写标题或不写。
- 项目要体现业务深度或技术深度。
- 写清楚是否主导设计过某个模块（0→1 或 1→2）。
- 尽可能展示指标数据，例如 QPS、数据量。
- 同样遵守：写在简历上的必须能聊。

### 2.4 简历自查

| 检查项 | 标准 |
| --- | --- |
| 结构 | 8 个部分完整 |
| 技能 | 必要技术 + 其他技术，能聊的才写 |
| 项目 | 有业务深度/技术深度，有指标 |
| 真实性 | 不夸张，难点和亮点可展开 |
| 引导性 | 能引导面试官问准备好的内容 |

## 3. 应届生怎么找练手项目

本节依次回答：3.1 项目来源、3.2 怎么学一个项目、3.3 应该学习哪些模块、3.4 怎么吃透一个模块。

### 3.1 项目来源

- Gitee/GitHub 搜索感兴趣的技术点或业务点。
- 黑马程序员 B 站项目课程。
- B 站搜索其他项目。
- 播客、文章。
- Gitee/GitHub 上其他相关项目。

### 3.2 怎么学一个项目

1. 本地快速运行起来，debug 跟踪代码逻辑。
2. 梳理完业务后，判断自己能否独立完成。
3. 找一两个点深度挖掘，多方位参考。
4. 目标：增加简历项目的业务深度、技术含金量和真实度。

### 3.3 应该学习哪些模块

通用模块清单：

- 权限认证
- 文件服务
- 日志
- 搜索
- 秒杀
- 支付
- 缓存
- SaaS
- 订单
- 优惠券
- CMS
- 报表

### 3.4 怎么吃透一个模块

以**权限认证**为例，回答三个问题：

| 层次 | 内容 |
| --- | --- |
| 功能实现 | 用户名密码登录、二维码登录、手机短信登录；用户、角色、权限管理和分配 |
| 技术方案 | RBAC 模型、Spring Security 或 Apache Shiro |
| 常见问题 | token 刷新、加密解密、XSS 防跨站攻击 |
| 系统设计 | 可扩展性、高可用性、通用性 |

**回答模板**：不要只说“做过权限”，要按“功能实现 → 技术方案 → 常见问题 → 系统设计”四层展开。

## 4. 面试过程

本节依次回答：4.1 面试轮次、4.2 面试官角色、4.3 自我介绍。

### 4.1 面试轮次

| 公司类型 | 轮次 |
| --- | --- |
| 中小企业、创业公司、外包 | 单轮技术面或多轮 |
| 上市公司、大厂 | 两轮、三轮甚至 N 轮技术面 |
| 大部分公司 | 一、二轮技术面 + HR 终面 |

### 4.2 面试官角色

| 角色 | 关注点 |
| --- | --- |
| 资深开发/技术经理 | 技术最好，多数参与首轮 |
| 业务部门经理 | 技术一般，多数参与终面，可决定薪资；看思考能力、抗压能力 |
| HR | 辅助考察性格、沟通能力、合作能力、学习能力 |

### 4.3 自我介绍

**结构：总分**

> 我叫什么，我的工作经历主要分为 3 个阶段：
> 1. xxxx
> 2. xxxx
> 3. xxxx

**项目讲解示例**

> 主导设计文章发布审核、延时发布等技术方案的选型和实现。

面试官可能追问：

- 审核什么内容？
- 什么技术实现的审核？
- 延时发布是用 Redis 还是 RabbitMQ？

**要点**：自我介绍里埋下的每个点都要能展开；准备 + 复盘。

## 5. 准备与心态

- 《孙子兵法》：求其上，得其中；求其中，得其下；求其下，必败。
- 找出自己的不足，针对性补强。
- 面试后复盘：哪些问题答不上来、哪些项目细节没讲清。
- 心态：要么学历牛逼，要么技术牛逼，要么都牛逼；学历无法改变，就让技术牛逼。

**行动清单**

| 阶段 | 动作 |
| --- | --- |
| 投递前 | 按岗位改简历，准备 2–3 个能讲透的项目 |
| 面试前 | 复习项目难点、技术选型、指标数据 |
| 面试中 | 总分结构表达，遇到不会的坦诚并给思路 |
| 面试后 | 复盘问题，补短板 |
