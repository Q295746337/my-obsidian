# 04-框架篇 面试笔记

> 范围：Spring 单例 Bean、AOP、事务、Bean 生命周期与循环依赖、SpringMVC 执行流程、SpringBoot 自动配置、MyBatis 执行流程与缓存。
> 主笔记：[[SSM框架/SSM框架 索引|SSM]]、[[SpringBoot2/SpringBoot2 索引|SpringBoot2]]。源码细节以主笔记为准。

## 1. Spring 单例 Bean 是线程安全的吗

**结论**：不是线程安全的，但通常不会有问题。

- `@Scope` 默认值是 `singleton`，一个容器中只有一个实例。
- Spring Bean 一般是无状态的（Service、DAO），没有可修改的成员变量，所以没有线程安全问题。
- 如果 Bean 中定义了可修改的成员变量，就需要考虑线程安全，可以用多例或加锁解决。

**易错点**

- “单例”只说明实例只有一个，不代表多线程安全。
- 有状态 Bean 不能只靠 singleton 保证安全。

## 2. AOP

本节依次回答：2.1 什么是 AOP、2.2 项目中怎么用 AOP 记录日志。

### 2.1 什么是 AOP

AOP 是面向切面编程，把与业务无关、但会影响多个对象的公共行为和逻辑抽取封装成切面，减少重复代码、降低耦合、提高可维护性。

**常见场景**

- 记录操作日志
- 缓存处理
- Spring 内置的事务处理

### 2.2 项目中怎么用 AOP 记录日志

- 使用环绕通知 + 切点表达式定位要记录日志的方法。
- 通过 `ProceedingJoinPoint` 获取类、方法、注解、请求方式等参数。
- 记录用户名、请求方式、访问地址、模块名称、登录 IP、操作时间到日志表。

```java
@Around("pointcut()")
public Object around(ProceedingJoinPoint joinPoint) throws Throwable {
    // 获取用户名、请求方式、模块名称、登录 IP 等
    Object result = joinPoint.proceed();
    // 保存操作日志到数据库
    return result;
}
```

**易错点**

- 切点要精确，避免把不需要记录的方法也拦截。
- 环绕通知里要调用 `proceed()`，否则目标方法不会执行。

## 3. Spring 事务

本节依次回答：3.1 两种事务管理、3.2 事务失效的三种场景。

### 3.1 两种事务管理

| 方式 | 实现 | 特点 |
| --- | --- | --- |
| 编程式事务 | `TransactionTemplate` | 对业务代码有侵入性，项目中很少使用 |
| 声明式事务 | `@Transactional`，基于 AOP | 对方法前后拦截，把事务编织到方法中 |

声明式事务本质：在目标方法执行前开启事务，执行完后根据执行情况提交或回滚。

### 3.2 事务失效的三种场景

| 场景 | 原因 | 解决 |
| --- | --- | --- |
| 异常被捕获 | 自己处理了异常，没有抛出，事务管理器感知不到 | 手动抛出异常 |
| 抛出检查异常 | 默认只回滚 RuntimeException 和 Error | 配置 `rollbackFor = Exception.class` |
| 非 public 方法 | Spring AOP 代理无法拦截非 public 方法 | 改为 public |

**回答模板**

> Spring 事务基于 AOP，常见失效有三类：异常被 catch、抛出检查异常、方法不是 public。分别通过手动抛出、配置 rollbackFor、改为 public 解决。

## 4. Bean 生命周期与循环依赖

本节依次回答：4.1 Bean 的创建流程、4.2 什么是循环依赖、4.3 三级缓存、4.4 构造方法循环依赖。

### 4.1 Bean 的创建流程

1. 通过 BeanDefinition 获取 Bean 的定义信息。
2. 调用构造函数实例化 Bean。
3. Bean 的依赖注入。
4. 处理 Aware 接口（BeanNameAware、BeanFactoryAware、ApplicationContextAware）。
5. BeanPostProcessor 前置处理。
6. 初始化方法（InitializingBean、init-method）。
7. BeanPostProcessor 后置处理。
8. 销毁 Bean。

**要点**：Bean 的创建和初始化赋值是分开的；AOP 代理通常在后置处理阶段生成。

### 4.2 什么是循环依赖

A 依赖 B，B 又依赖 A，形成闭环。Spring 允许循环依赖存在，并通过三级缓存解决大部分循环依赖。

### 4.3 三级缓存

| 缓存 | 源码名称 | 作用 |
| --- | --- | --- |
| 一级缓存 | singletonObjects | 单例池，缓存完整生命周期的 Bean |
| 二级缓存 | earlySingletonObjects | 缓存早期 Bean（生命周期未走完） |
| 三级缓存 | singletonFactories | 缓存 ObjectFactory，用于创建对象 |

- 一级缓存保证单例，但解决不了循环依赖。
- 二级缓存作为中间人打破循环。
- 三级缓存在需要时通过 ObjectFactory 生成代理对象，解决 AOP 代理下的循环依赖。

> 补充：来自新下载讲义。以 A、B 互相依赖为例，三级缓存的解决流程是：
>
> 1. 实例化 A，把 A 的 ObjectFactory 放入三级缓存。
> 2. A 初始化时发现需要 B，开始创建 B。
> 3. 实例化 B，把 B 的 ObjectFactory 放入三级缓存。
> 4. B 需要注入 A，从三级缓存取出 A 的 ObjectFactory 生成 A，并把 A 放入二级缓存。
> 5. B 拿到 A 后创建完成，放入一级缓存。
> 6. A 初始化时 B 已创建完成，直接注入 B，A 创建完成并放入一级缓存。
> 7. 清除二级缓存中的临时对象 A。

### 4.4 构造方法循环依赖

- 构造方法注入的循环依赖会报错：`Is there an unresolvable circular reference?`
- 原因：构造函数是 Bean 生命周期中第一个执行的，Spring 无法用三级缓存解决。
- 解决：使用 `@Lazy` 懒加载，需要对象时再创建。

```java
public A(@Lazy B b) {
    this.b = b;
}
```

## 5. SpringMVC 执行流程

本节依次回答：5.1 视图阶段（JSP）、5.2 前后端分离阶段。

### 5.1 视图阶段（JSP）

1. 用户请求到前端控制器 DispatcherServlet。
2. DispatcherServlet 调用 HandlerMapping。
3. HandlerMapping 找到处理器，生成处理器执行链 HandlerExecutionChain。
4. DispatcherServlet 调用 HandlerAdapter。
5. HandlerAdapter 适配调用 Handler/Controller。
6. Controller 返回 ModelAndView。
7. HandlerAdapter 把 ModelAndView 返回给 DispatcherServlet。
8. DispatcherServlet 传给 ViewResolver。
9. ViewResolver 解析并返回 View。
10. DispatcherServlet 渲染视图。
11. 响应用户。

### 5.2 前后端分离阶段

- 前 5 步相同。
- Controller 方法上加 `@ResponseBody`。
- 通过 HttpMessageConverter 把返回结果转为 JSON 并响应，不再经过视图解析器。

**易错点**

- `@RestController` = `@Controller` + `@ResponseBody`。
- 视图阶段和接口阶段的核心区别在返回值处理。

## 6. SpringBoot 自动配置

本节依次回答：6.1 三个核心注解、6.2 自动配置原理。

### 6.1 三个核心注解

`@SpringBootApplication` 封装了：

| 注解 | 作用 |
| --- | --- |
| `@SpringBootConfiguration` | 声明当前类是配置类，等同 `@Configuration` |
| `@ComponentScan` | 扫描当前引导类所在包及其子包 |
| `@EnableAutoConfiguration` | 自动配置的核心注解 |

### 6.2 自动配置原理

1. `@EnableAutoConfiguration` 通过 `@Import` 导入配置选择器。
2. 读取项目和依赖 Jar 包 classpath 下 `META-INF/spring.factories` 中配置的类。
3. 配置类中的 Bean 根据条件注解决定是否导入。
4. 例如 `@ConditionalOnClass` 判断是否有对应 class，有才加载。

**回答模板**

> `@SpringBootApplication` 是三个注解的组合；`@EnableAutoConfiguration` 通过 `@Import` 导入选择器，读取 `spring.factories` 中的自动配置类，再由条件注解按需装配 Bean。

## 8. MyBatis

本节依次回答：8.1 执行流程、8.2 延迟加载、8.3 一级缓存与二级缓存。

### 8.1 执行流程

1. 读取 `mybatis-config.xml`，加载运行环境和映射文件。
2. 构造会话工厂 SqlSessionFactory（全局一个）。
3. 会话工厂创建 SqlSession（每次操作一个会话）。
4. 通过 Executor 执行器操作数据库，同时维护查询缓存。
5. Executor 方法中的 MappedStatement 封装映射信息。
6. 输入参数映射、输出结果映射。

### 8.2 延迟加载

- 立即加载：查询用户时把订单也查出来。
- 延迟加载：查询用户时不查订单，用到订单时再查。
- 原理：用 CGLIB 创建目标对象的代理对象；调用 `user.getOrderList()` 时进入拦截器，发现是 null 就执行 SQL 查询，再调用 set 方法赋值。
- 配置：`lazyLoadingEnabled=true|false`，默认关闭。

### 8.3 一级缓存与二级缓存

| 缓存 | 作用域 | 默认 | 说明 |
| --- | --- | --- | --- |
| 一级缓存 | SqlSession | 开启 | 基于 PerpetualCache 的 HashMap；Session flush 或 close 后清空 |
| 二级缓存 | namespace/mapper | 关闭 | 基于 namespace 和 mapper，需要单独开启 |

二级缓存开启两步：

```xml
<settings>
    <setting name="cacheEnabled" value="true"/>
</settings>
```

```xml
<cache/>
```

**注意事项**

- 新增、修改、删除后，默认清空该作用域下所有 select 缓存。
- 二级缓存的数据需要实现 Serializable 接口。
- 只有会话提交或关闭后，一级缓存数据才会转移到二级缓存。

| 单例 Bean 线程安全 | 默认无状态所以安全；有成员变量要考虑并发 |

| MyBatis 流程 | 配置文件 → SqlSessionFactory → SqlSession → Executor → MappedStatement |
| 延迟加载 | CGLIB 代理，用到时再查 |
| 缓存 | 一级 Session 默认开；二级 namespace 默认关 |
