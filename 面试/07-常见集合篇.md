## 1. 复杂度分析

本节依次回答：1.1 时间复杂度、1.2 空间复杂度。

### 1.1 时间复杂度

复杂度分析解决的是代码“快”和“省”的问题：执行效率看时间，存储占用看空间。

- 时间复杂度评估代码执行耗时随数据规模增长的趋势，用大 O 表示法。
- 低阶、常量、系数在 n 很大时不影响增长趋势，可以忽略。

| 复杂度 | 名称 |
| --- | --- |
| O(1) | 常数 |
| O(log n) | 对数 |
| O(n) | 线性 |
| O(n log n) | 线性对数 |
| O(n²) | 平方 |
| O(n³) | 立方 |
| O(2ⁿ) | 指数 |
| O(n!) | 阶乘 |

速记：常对幂指阶。

### 1.2 空间复杂度

- 表示算法占用的额外存储空间与数据规模之间的增长关系。
- 常见：O(1)、O(n)、O(n²)。

## 2. 数组

本节依次回答：2.1 结构、2.2 为什么索引从 0 开始、2.3 操作复杂度。

### 2.1 结构

- 数组用连续内存空间存储相同数据类型的元素。
- 通过首地址 + 索引 × 元素大小计算元素地址，随机访问 O(1)。

### 2.2 为什么索引从 0 开始

寻址公式：`a[i] = baseAddress + i * dataTypeSize`。

如果索引从 1 开始，公式需要多一次减法，对 CPU 来说多一条指令，性能略低。

### 2.3 操作复杂度

| 操作 | 复杂度 |
| --- | --- |
| 按下标随机查询 | O(1) |
| 未知下标查找 | O(n) |
| 排序后二分查找 | O(log n) |
| 插入/删除 | 平均 O(n) |

插入删除需要挪动元素，保证内存连续性。

## 3. ArrayList

本节依次回答：3.1 底层原理、3.2 添加与扩容、3.3 `new ArrayList(10)` 扩容几次、3.4 数组与 List 互转。

### 3.1 底层原理

- 底层是动态数组 `Object[] elementData`。
- 默认初始容量为 0，第一次添加数据时初始化为 10。
- 扩容为原容量的 1.5 倍，每次扩容都要拷贝数组。
- `size` 记录实际元素个数。

```java
private static final int DEFAULT_CAPACITY = 10;
transient Object[] elementData;
private int size;
```

### 3.2 添加与扩容

1. 确保数组已使用长度 `size + 1` 足够存下一个数据。
2. 计算容量，如果 `size + 1` 大于当前数组长度，调用 `grow` 扩容。
3. 扩容为原容量的 1.5 倍，用 `Arrays.copyOf` 拷贝。
4. 把新元素放到 `size` 位置，返回成功。

```java
int newCapacity = oldCapacity + (oldCapacity >> 1);
elementData = Arrays.copyOf(elementData, newCapacity);
```

### 3.3 `new ArrayList(10)` 扩容几次

**答案：0 次。**

该语句只是声明并实例化 ArrayList，指定容量为 10，此时数组已按 10 创建，未发生扩容。

**易错点**

- 无参构造 `new ArrayList()` 初始容量不是 10，而是空数组；第一次 add 才初始化 10。
- 扩容是 1.5 倍，不是 2 倍。

### 3.4 数组与 List 互转

```java
// 数组转 List
String[] strs = {"aaa", "bbb", "ccc"};
List<String> list = Arrays.asList(strs);

// List 转数组
List<String> list2 = new ArrayList<>();
String[] array = list2.toArray(new String[list2.size()]);
```

**追问：修改原数组，List 会受影响吗？**

- 会。`Arrays.asList` 返回的是 Arrays 内部类 ArrayList，构造器只是包装传入数组，底层指向同一内存地址。
- 修改 List，`toArray` 返回的数组不受影响，因为 toArray 进行了数组拷贝。

**易错点**

- `Arrays.asList` 返回的 List 不支持增删，长度固定。
- 需要真正独立的 List 时，要新建 ArrayList 再拷贝。

## 4. LinkedList

本节依次回答：4.1 单向链表、4.2 双向链表、4.3 ArrayList 与 LinkedList 的区别。

### 4.1 单向链表

- 每个节点包含数据域和指向下一个节点的 next 指针。
- 物理存储非连续、非顺序。
- 查询头节点 O(1)，其他节点 O(n)。
- 头节点增删 O(1)，其他节点需要先遍历，O(n)。

### 4.2 双向链表

- 每个节点有 next 和 prev 两个指针。
- 支持双向遍历。
- 查询头尾 O(1)，平均 O(n)，给定节点找前驱 O(1)。
- 头尾增删 O(1)，给定节点增删 O(1)，其他 O(n)。

| 类型 | 查询 | 新增删除 |
| --- | --- | --- |
| 单向链表 | 头 O(1)，其他 O(n) | 头 O(1)，其他 O(n) |
| 双向链表 | 头尾 O(1)，其他 O(n)，给定节点 O(1) | 头尾 O(1)，给定节点 O(1)，其他 O(n) |

### 4.3 ArrayList 与 LinkedList 的区别

| 维度 | ArrayList | LinkedList |
| --- | --- | --- |
| 底层结构 | 动态数组 | 双向链表 |
| 下标查询 | O(1) | 不支持下标查询 |
| 未知索引查找 | O(n) | O(n) |
| 增删 | 尾部 O(1)，其他 O(n) | 头尾 O(1)，其他 O(n) |
| 内存 | 连续内存，节省 | 每个节点多两个指针，更占内存 |
| 线程安全 | 否 | 否 |

线程安全方案：

- 方法内使用局部变量，天然线程安全。
- 使用 `Collections.synchronizedList` 包装。

## 5. 树结构

本节依次回答：5.1 二叉树、5.2 二叉搜索树、5.3 红黑树。

### 5.1 二叉树

- 每个节点最多两个子节点：左子节点、右子节点。
- 不要求每个节点都有两个子节点。
- 常见类型：满二叉树、完全二叉树、二叉搜索树、红黑树。

### 5.2 二叉搜索树

- 任意节点的左子树所有节点值小于该节点，右子树所有节点值大于该节点。
- 没有键值相等的节点。
- 通常情况下查找、插入、删除为 O(log n)。
- 极端情况下退化成链表，复杂度变为 O(n)。

### 5.3 红黑树

红黑树是自平衡的二叉搜索树，通过旋转保持平衡。

**五条性质**

1. 节点要么红色，要么黑色。
2. 根节点是黑色。
3. 叶子节点都是黑色空节点。
4. 红色节点的子节点都是黑色。
5. 从任一节点到叶子节点的所有路径都包含相同数目的黑色节点。

**复杂度**：查找、添加、删除都是 O(log n)；旋转调整是 O(1)。

## 6. 散列表

本节依次回答：6.1 结构、6.2 散列冲突。

### 6.1 结构

- 散列表根据 key 直接访问内存位置的数据结构，由数组演化而来。
- 散列函数把 key 映射为数组下标：`hashValue = hash(key)`。
- 散列值必须是非负整数，因为要作为数组下标。

### 6.2 散列冲突

不同的 key 可能映射到同一个数组下标，即哈希冲突。

**链表法（拉链）**

- 数组每个下标称为桶（bucket）或槽（slot）。
- 每个桶对应一条链表，冲突元素放入同一槽位的链表。
- 插入 O(1)；查找/删除平均 O(1)。
- 冲突严重时退化为链表，查询变 O(n)。
- 可以把链表改成红黑树，查询变 O(log n)。

**为什么改成红黑树**

- 除了性能，还能防止 DDoS 攻击：攻击者构造大量冲突 key，让散列表退化为链表。
- JDK 1.8 中链表长度大于 8 且数组长度大于 64 时转红黑树；扩容时红黑树拆分后的节点数小于等于 6 退化为链表。

## 7. HashMap

本节依次回答：7.1 实现原理、7.2 put 流程、7.3 扩容机制、7.4 寻址算法、7.5 JDK 1.7 多线程死循环。

### 7.1 实现原理

- 底层是哈希表：数组 + 链表或红黑树。
- put 时用 key 的 hashCode 重新计算 hash，得到数组下标。
- 下标位置为空直接插入；key 相同覆盖；key 不同放入链表或红黑树。
- get 时按 hash 找到下标，再比较 key。

**JDK 1.7 与 1.8 的区别**

| 版本 | 结构 | 冲突处理 |
| --- | --- | --- |
| 1.7 | 数组 + 链表 | 拉链法，头插法 |
| 1.8 | 数组 + 链表 + 红黑树 | 链表长度 > 8 且数组长度 > 64 转红黑树；扩容时 ≤ 6 退化 |

### 7.2 put 流程

1. 判断 table 是否为空或 null，为空则 `resize()` 初始化。
2. 根据 key 计算 hash，得到数组索引。
3. `table[i] == null`，直接新建节点。
4. 否则：
   - 首节点 key 相同，直接覆盖 value。
   - 首节点是红黑树节点，在树中插入。
   - 遍历链表，尾部插入；遍历中发现 key 相同则覆盖；链表长度大于 8 转红黑树。
5. 插入后判断 `size > threshold`（数组长度 × 0.75），超过则扩容。

**关键属性**

```java
static final int DEFAULT_INITIAL_CAPACITY = 1 << 4; // 16
static final float DEFAULT_LOAD_FACTOR = 0.75f;
transient Node<K,V>[] table;
transient int size;
```

- HashMap 是懒惰加载，无参构造不初始化数组，只设置加载因子 0.75。

### 7.3 扩容机制

- 第一次添加数据初始化数组长度为 16。
- 达到阈值（数组长度 × 0.75）时扩容。
- 每次扩容为原来的 2 倍，创建新数组并迁移数据。
- 无冲突节点：用 `e.hash & (newCap - 1)` 计算新位置。
- 红黑树：走红黑树拆分。
- 链表：遍历拆分，判断 `(e.hash & oldCap)` 是否为 0；为 0 留在原位置，否则移到原位置 + oldCap。

### 7.4 寻址算法

```java
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

- 二次哈希：hashCode 右移 16 位再异或，让哈希分布更均匀，减少冲突。
- 索引：`(n - 1) & hash`，代替取模，性能更好。

**为什么数组长度一定是 2 的次幂**

1. 计算索引时可以用位与代替取模，效率更高。
2. 扩容时重新计算索引效率更高：`hash & oldCap == 0` 留在原位置，否则新位置 = 旧位置 + oldCap。

### 7.5 JDK 1.7 多线程死循环

- 1.7 数据结构是数组 + 链表，扩容迁移时使用头插法。
- 两个线程同时扩容，线程 2 先把链表顺序颠倒，线程 1 继续迁移时可能形成 `B → A → B` 的环。
- 结果：get 时死循环，CPU 飙高。
- JDK 1.8 改为尾插法，保持扩容前顺序，避免该问题。

**易错点**

- 1.8 解决的是扩容死循环，不代表 HashMap 线程安全。
- 并发场景应使用 ConcurrentHashMap。

## 8. 面试速记

| 问题 | 一句话答案 |
| --- | --- |
| 数组下标从 0 开始 | 寻址公式少一次减法，CPU 指令更少 |
| ArrayList 扩容 | 第一次 add 初始化 10，之后 1.5 倍拷贝 |
| new ArrayList(10) | 不扩容 |
| 数组转 List | Arrays.asList 包装，改数组会影响 List |
| List 转数组 | toArray 拷贝，互不影响 |
| ArrayList vs LinkedList | 数组 vs 双向链表；查询与增删各有优势 |
| 红黑树 | 自平衡 BST，查/增/删 O(log n) |
| 散列冲突 | 拉链法；链表过长转红黑树，防 DDoS |
| HashMap 结构 | 数组 + 链表/红黑树；1.8 链表 > 8 且数组 ≥ 64 转树 |
| HashMap 扩容 | 初始 16，阈值 0.75，2 倍扩容，拆分链表 |
| 2 的次幂 | 位与代替取模；扩容定位更高效 |
| 1.7 死循环 | 头插法导致链表成环，1.8 改尾插法 |
