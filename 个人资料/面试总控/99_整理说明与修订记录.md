## 三、已修正的问题

### 3.1 乡兴未来：旧《05_简历事实对照与速查卡》把“你”写成了李财源

**问题**：旧文件写“团队：3 人，你是负责人（李财源，计科 2301）”“说‘我是项目负责人，牵头 UE5 引擎开发’”。这是明显的身份错误——简历主人是刘倚岐，团队负责人是李财源。

**处理**：

- 已将 05 卡片中的“你是负责人（李财源）”改为“你是刘倚岐，简历写核心开发；团队负责人是李财源”。
- 已将“负责人 / 核心开发”的简历建议改回“核心开发”。
- 已将“我做负责人牵头 UE5 引擎开发”改为“我是核心开发，主攻工程线”。
- 在 00 总览和 02 速查中明确：**乡兴不称负责人**。

**仍需注意**：05 卡片是早期资料，部分表述（如“确认你是三人中的哪一位”）已过时；以 00 总览和 02 速查为准。

### 3.2 乡兴未来：04 行为面“我是负责人”已修正

**问题**：04 的 HR 问题 Q1 原写“我们是三人小团队，我是负责人……”，与简历和事实不符。

**处理**：改为“我是核心开发，主要负责工程线；团队负责人统筹……”，并保留“分工明确、定期同步、共同攻坚”的要点。

### 3.3 乡兴未来：03 技术篇“队友负责传送/打包”与事实矛盾

**问题**：03 原写“队友分别负责建模表现层，以及传送/打包等环节”，但报告书中传送/三端打包是刘倚岐的原始分工之一，且与“工程线我负责”的定位矛盾。

**处理**：改为“队友负责建模表现层；传送/打包等工程环节我也参与/负责”，避免把用户自己的经历推给队友。

### 3.4 个人简历说明书：几处不准确/过度表述

| 原表述 | 问题 | 处理 |
|---|---|---|
| “独立完成 3 个项目” | 三个项目均为团队项目，简历写“核心开发”，不是独立完成 | 改为“作为核心开发参与 3 个项目” |
| “熟练掌握 SpringBoot、Redis、Kafka 等” | 简历写“熟悉 Kafka、RabbitMQ”，不是“熟练掌握” | 改为“熟悉 SpringBoot、Redis、Kafka 等” |
| “部分技术深度仍有欠缺，复杂场景下的问题处理经验有待积累” | 太笼统、自我否定，面试官抓不到重点 | 在 00 总览第 6.3 节改写为四条具体不足 + 改进动作 |

### 3.5 旧《我的档案》：只写两个项目、自我设限

**问题**：

- 只写“两个代表性项目”，漏掉简历第一项目“伊岐优选”。
- 写“深度定位：上手做过、能讲原理，但不钻某个模块的底层细节”——这会自我设限；Java 后端主线（伊岐优选）应按知识库深度准备。
- 把“两个项目”都按“全流程参与”讲，但没有区分主航道和差异化。

**处理**：将《我的档案》重写为“已升级为总览”的说明页，保留仍然有效的定位，指向 00 总览。新定位是：

- 三个项目都按“核心开发/全程参与”讲，能讲整体架构、数据流、关键机制，不把自己框死在一个模块。
- 伊岐优选是 Java 后端主航道，深度最高；变电站是分布式/并发/架构证明；乡兴是跨端/AI/Web 差异化。

- 乡兴不称负责人；建模是队友主力，工程线是主攻。

## 六、维护流程（以后怎么更新）

### 6.1 新事实/新项目

1. 先更新 [[个人资料/面试总控/02_三项目事实与口径速查]]（事实层）。
2. 再更新 [[个人资料/面试总控/00_个人资料总览]]（叙事层）。
3. 最后按需更新项目复习包。
4. 不直接改简历（简历已定型）。

### 6.2 新公司 JD

1. 在 `秋招面试公司/<公司>/` 放招聘要求。
2. 引用 00 + 02 + 01，按 01 的 Prompt 生成 `01_面试复习资料.md`。
3. 面试后填 `03_面试复盘.md`，把新问题/新口径回填 00/02。

### 6.3 面试后发现口径错误

1. 先判断是“事实错误”还是“表达问题”。
2. 事实错误：更新 02 + 项目包；表达问题：更新 00 第 8 节。
3. 在 99 的“修订记录”里加一条日期 + 修改内容，避免以后又用旧口径。

### 6.4 不要做的事

- 不要为了匹配 JD 编造项目、头衔、数字。
- 不要把“了解/熟悉”升级成“精通”。
- 不要把乡兴说成“负责人”、伊岐说成“从零自研”、变电站说成“生产系统”。
- 不要把敏感个人信息（身份证号、出生日期、家庭住址）写进面试资料。
