# 岗位定制面试复习资料 · 生成规范（可复用）

> **用途**：拿到任意公司的招聘要求（JD）后，用本规范 + [[个人资料/面试总控/00_个人资料总览]] + 目标岗位笔记，生成一套“一岗一策、可直接背、事实可追溯”的面试复习资料。
>
> **核心原则**：先拆 JD，再匹配我的证据，最后才生成题目；不先写通用八股，不编造项目经历，不把“了解”说成“精通”。
>
> **配套文件**：
> - [[个人资料/面试总控/00_个人资料总览]]（人物 + 项目 + 口径）
> - [[个人资料/面试总控/02_三项目事实与口径速查]]（项目事实 + 追问索引）
> - [[个人资料/面试总控/99_整理说明与修订记录]]（来源与待确认项）

---

## 1. 这套方法解决什么问题

| 常见问题 | 这套方法的做法 |
|---|---|
| 每次换公司都要重新解释“我是谁、做过什么” | 00 总览作为稳定上下文，一次维护、反复引用 |
| 生成的资料很泛，和 JD 对不上 | 先做 JD 考点拆解 + 匹配矩阵，再决定复习优先级 |
| AI 编造项目、数字、头衔 | 事实分级 + 反幻觉规则 + 事实核对表 |
| 资料太长，考前看不完 | 标准版/突击版两种输出；按优先级和时间预算裁剪 |
| 面试完就丢了，下一次又从零开始 | 面试复盘模板 + 回填 00/02/项目包 |

## 2. 输入清单（开工前 5 分钟）

### 必填

| 输入 | 说明 |
|---|---|
| **目标 JD 全文** | 直接引用目标公司招聘要求笔记，或粘贴 JD 原文 |
| **公司/岗位/轮次** | 公司名、岗位名、一面/二面/HR 面、面试时间 |
| **个人总览** | [[个人资料/面试总控/00_个人资料总览]] |
| **项目事实** | [[个人资料/面试总控/02_三项目事实与口径速查]] + 对应项目复习包 |
| **知识库范围** | JavaSE、JavaWeb、JUC、JVM、MySQL、Redis、SSM、SpringBoot2、微服务、AI、面试、八股文、黑马点评 |

### 选填

- 公司业务/产品/面经（越具体越好）。
- 我的薄弱项（如“微服务没项目经验”“手撕算法弱”“AI 原理不熟”）。
- 可用复习时间（如 3 天 / 1 天 / 2 小时）。
- 已复习进度（哪些专题已过、哪些没看）。

### 缺失处理

- JD 不完整：标注“JD 缺失，以下按岗位名称推断”，不要编造具体要求。
- 公司信息少：只做技术匹配，不编公司业务。
- 时间紧：自动切“突击版”，只保留最高优先级。

## 3. 四阶段工作流

### 阶段 1：JD 拆解（先输出考点表，不急着写答案）

把 JD 拆成四类：

| 类型 | 标记 | 说明 |
|---|---|---|
| 硬性必掌握 | 🔴 | 岗位明确要求、必须 100% 准备 |
| 加分项 | 🟡 | 优先录取、有则加分 |
| 业务方向 | 🔵 | 公司/岗位业务领域，需要提前了解 |
| 软素质 | 🟢 | 沟通、学习、团队、抗压等 |

每条要求再标注：

- **我的证据**：哪个项目/课程/竞赛/知识库能支撑。
- **匹配度**：强 / 中 / 弱 / 无。
- **策略**：主推项目 / 知识补课 / 诚实话术 / 不主动提。

**输出表模板**：

```markdown
| # | JD 要求 | 类型 | 我的证据 | 匹配度 | 策略 |
|---|---|---|---|---|---|
| 1 | 熟悉 Spring Boot | 🔴 | 伊岐优选、变电站 | 强 | 主推伊岐，讲自动配置/拦截器/事务 |
| 2 | 熟悉 Spring Cloud | 🔴 | 无项目证据；知识库有 | 弱 | 知识补课 + 诚实说“学过未实战” |
```

### 阶段 2：叙事策略（决定主推哪个项目）

根据 JD 选择 1–2 个主推项目，1 个备选：

| 岗位类型 | 主推 | 辅助 | 一句话策略 |
|---|---|---|---|
| Java 后端/电商/高并发 | 伊岐优选 | 变电站 | 用秒杀/缓存/MQ 打透后端深度 |
| 分布式/中间件/基础架构 | 变电站 | 伊岐优选 | 用黑板架构/多进程/锁证明架构能力 |
| AI 应用/Agent/全栈 | 伊岐优选（AI 客服） | 乡兴（AI 向导 + Web） | 用 Function Calling/RAG/会话隔离打差异化 |
| 游戏/UE/数字孪生 | 乡兴未来 | 变电站 | 用 UE 交互/三端/VR/WebSocket 打匹配 |
| 国企/电网/研究所 | 变电站 | 伊岐 + 乡兴 | 用行业场景/分布式/可视化打稳定可靠 |
| 全栈/前端 | 乡兴（网站） | 伊岐 + 变电站 | 用网站前后端闭环 + 后端能力打全栈 |

**叙事三句话**（生成资料开头就要有）：

1. 我是谁：一句话画像。
2. 我为什么匹配这个岗位：3 条证据。
3. 我有什么差距：1 条诚实话术 + 补法。

### 阶段 3：资料生成（严格按第 4 节模板）

生成时遵守：

- **先结论后展开**：每个答案第一句是结论，然后 2–3 点理由，最后 1 个项目例子。
- **答案可口头复述**：单题 60–90 秒能讲完；不要写成论文。
- **每个技术点挂项目**：八股不是孤立背诵，尽量挂到伊岐/变电站/乡兴。
- **每个数字带口径**：实测/设计目标/自测/笔记压测。
- **每个知识点给来源**：链接到知识库笔记或项目复习包。
- **不编造**：简历没有的项目、头衔、数字，一律不写；需要时标“建议补充/待确认”。

### 阶段 4：质量自检（Gate）

生成后逐项检查：

- [ ] 每条 🔴 硬性要求都有“证据/补课/诚实话术”三种处理之一。
- [ ] 主推项目不超过 2 个，备选不超过 1 个。
- [ ] 所有数字都有口径标签。
- [ ] 没有“独立完成/负责人/精通/主导”等超出简历的表述。
- [ ] 乡兴没有称“负责人”；伊岐没有称“从零自研”；变电站没有称“生产系统”。
- [ ] AI 辅助、课程项目、黑马点评来源都有诚实口径。
- [ ] 每题答案 60–90 秒能讲完；没有超长段落。
- [ ] 至少 3 条项目追问链（技术→难点→不足→改进）。
- [ ] 反问问题不涉及薪资/加班。
- [ ] 事实核对表完整（头衔/时间/数字/技术词）。

## 7. 面试后复盘与迭代

每次面试结束 10 分钟内填 [[#11. 面试后复盘（面试结束 10 分钟内填）|复盘]]，然后做三件事：

1. **回填事实**：新确认的项目细节/数字/技术词，更新到 [[个人资料/面试总控/02_三项目事实与口径速查]] 或对应项目包。
2. **回填口径**：被问穿/答不好的点，更新到 [[个人资料/面试总控/00_个人资料总览#8. 面试口径与红线（考前背这一页）]]。
3. **回填题库**：新问题加到该公司复习资料；高频问题沉淀到 00 的“高频追问”或知识库。

**迭代原则**：

- 不重复造轮子：同一问题第二次出现，直接引用已有答案。
- 不删除历史：旧版本保留，标注日期和公司，方便对比。
- 每次只改“事实/口径”，不因一次面试失败就否定整个画像。

## 8. 示例：如何套用到现有两个 JD

### 8.1 图观（天津）· Java 开发工程师

**JD 关键词**：Java 基础、JVM、多线程、集合、Spring Boot、Spring Cloud、MySQL/SQL 优化、Redis、消息队列、Git/Maven、单元测试、沟通协作。

**主推**：伊岐优选（主）+ 变电站（辅）。

**策略**：

- 强匹配：Java 基础、JUC、JVM、MySQL、Redis、MQ、Spring Boot、Git/Maven、单元测试。
- 弱匹配：Spring Cloud/微服务（无项目经验）→ 知识补课 + 诚实说“学过原理，项目里没用过”；用变电站的“多进程解耦/消息总线”类比微服务治理思想，但不要谎称微服务项目。
- 项目排序：伊岐（秒杀/缓存/MQ）→ 变电站（分布式/并发/联调）→ 乡兴（AI/全栈，作为差异化一句带过）。
- 高频追问：秒杀一致性、Kafka 可靠性、缓存三兄弟、JVM 调优、线程池、Spring 事务、SQL 索引。

### 8.2 先特网络 · Java 实习生

**JD 关键词**：Java、面向对象、Spring Boot、Spring Cloud、RESTful API、单元测试、MySQL/SQL 调优、Redis、Elasticsearch、Kafka、Git/Maven。

**主推**：伊岐优选（主）+ 变电站（辅）。

**策略**：

- 强匹配：Java、Spring Boot、MySQL、Redis、Kafka、Git/Maven、单元测试。
