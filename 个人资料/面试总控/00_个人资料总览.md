## 5. 项目卡片

### 5.1 伊岐优选（Java 后端主航道）

**一句话**：

> 基于 SpringBoot 的本地生活服务平台，核心做了优惠券秒杀、缓存治理、接口限流和 LangChain4j AI 智能客服。

**事实定位（必须记住）**：

- 简历名：**伊岐优选**；项目原型/学习基础：**黑马点评**（旧资料里也叫“雅鉴生活志”）。
- 性质：**基于黑马点评的二次开发 + 功能扩展 + 换名**，不是从零自研的平台。
- 面试口径：可以坦诚“这是基于开源学习项目做的改造”，然后把重点放在**我新增/优化了什么、为什么这么做、怎么验证**。不要声称“从零设计并开发了整个点评平台”。

**我的角色与深度**：

- 简历写“核心开发”；实际主线是秒杀、缓存、限流、AI 客服四条。
- 这是三个项目里**最適合深挖 Java 后端**的一个；JUC、Redis、MySQL、Kafka、Spring 的八股都可以往这里挂。
- 能讲到：Lua 脚本原子性、Kafka 异步削峰、逻辑过期 vs 互斥锁、Caffeine+Redis 两级缓存、滑动窗口 Lua、LangChain4j 工具调用/RAG/会话隔离。

**四条技术主线**：

1. **秒杀下单与异步处理**
   - Redis + Lua 原子校验：库存判断 + 一人一单（Set/Hash 记录购买用户）。
   - Kafka 异步下单、削峰；消费端扣库存、生成订单；订单 ID 唯一保证幂等。
   - SpringTask 定时关闭超时未支付订单；支付回调与关单用乐观锁（`where status = '未支付'`）保证只有一个成功。
   - 结果：库存不超卖、订单不重复；失败场景用对账/补偿兜底。
2. **缓存与数据一致性**
   - Caffeine 本地缓存 + Redis 分布式缓存两级架构；热 key 压力分散到应用内存。
   - 逻辑过期防热点 key 击穿；缓存空值防穿透；TTL 兜底。
   - 更新数据库后删除缓存；删除失败经 Kafka 重试；仍失败告警/人工介入。
   - 取舍：逻辑过期保可用性、牺牲强一致；金融类强一致场景才用互斥锁。
3. **接口限流**
   - Redis + AOP + 自定义注解实现滑动窗口限流；支持全局、IP、用户多维度。
   - 防刷券、爬虫、系统过载；限流算法对比（固定窗口/滑动窗口/令牌桶/漏桶）要能讲。
4. **AI 智能客服**
   - LangChain4j 接入大模型（项目实现为 qwen-plus 兼容接口）；Function Calling 调用店铺查询、优惠券查询、预约到店等工具。
   - Redis 会话记忆：窗口（最近 N 条）+ 归档（完整历史）+ 用户会话索引；登录态绑定，防越权看别人会话。
   - RAG：Redis 向量库 + 知识库导入 + 意图路由（业务数据走工具，泛知识走 RAG）。
   - 流式输出：WebFlux `Flux` + Nginx 关闭缓冲 + 前端 `ReadableStream`。
   - 工程细节：手机号服务端绑定、预约校验、N+1 批量查询、API Key 环境变量、ThreadLocal 清理。

**关键数字（带口径）**：

| 数字 | 口径 |
|---|---|
| 秒杀 QPS 1000、200 库存，平均响应 500ms→176ms | 项目笔记压测（本地环境），面试说“笔记里的压测数据” |
| 二级缓存吞吐 18,970（MySQL）→57,769（Redis）→93,930（Caffeine+Redis）req/s | 项目笔记压测；较 MySQL 4.95×、较 Redis 1.63× |
| 平均延迟 52.47ms→17.19ms→10.53ms | 同上 |

**高频追问（先背问题，答案去链接）**：

1. 为什么用 Lua？Redis 单线程 + Lua 原子性，库存判断和一人一单不会被并发打断。
2. 为什么用 Kafka 而不是同步扣库存？秒杀接口只做资格判断，扣库存/生成订单异步做，提升吞吐。
3. Kafka 消息丢失/重复/顺序怎么处理？至少一次 + 唯一订单 ID 幂等 + 失败重试/死信/对账。
4. 为什么逻辑过期而不是互斥锁？热点数据可用性优先，允许短暂旧数据；强一致场景才用互斥锁。
5. 缓存和数据库怎么保证一致？更新 DB 后删缓存 + Kafka 重试 + TTL 兜底；最终一致，不是强一致。
6. Caffeine 和 Redis 有什么区别？本地内存快但集群不一致；Redis 共享但多一跳网络；热 key 用本地缓存。
7. 滑动窗口怎么实现？Redis ZSet/Lua 记录时间戳，统计窗口内请求数；AOP 注解切面拦截。
8. RAG 和 Function Calling 怎么分工？RAG 答“资料里的泛知识”，Function Calling 查“数据库里的实时业务数据”。
9. 怎么防止用户查别人的券/预约？工具不接收手机号，查询主体从登录态取；memoryId 绑定 userId 并二次校验。
10. 这个项目和黑马点评是什么关系？基于开源项目二次开发，重点讲我改造/新增的部分。

### 5.3 分布式探索仿真系统（变电站，分布式/并发/架构）

**一句话**：

> 基于黑板架构的变电站多车协同巡检仿真：Redis 当共享黑板、RabbitMQ 当消息总线、Controller 当唯一调度器，多车协作探索地图并实时可视化。

**事实定位（必须记住）**：

- 性质：**课程项目**（软件工程 + 软件体系结构两门课，3 学分，4 人小组），**大量借助 AI 辅助开发，非生产系统**。
- 时间：2026.05–2026.07；简历角色：核心开发。
- 架构：**9 个 Maven 模块 = 7 个独立进程 + common 公共库 + launcher 可选启动器**。
- 7 进程：TaskConfigurator / Navigator / TargetPlanner / StrategySupervisor / Car / Display / Controller。
- 通信：业务模块只依赖 common，互不直接调用；Redis 存状态，RabbitMQ 传消息，Controller 唯一中转。
- Controller 单实例：`SET controller:instance 1 NX EX 30`。
- 节拍：默认 500ms，可调 100–2000ms。

**我的角色与深度**：

- 简历写“核心开发”；定稿口径是“全程参与、各模块都能讲清”，理解最透的是 500ms 调度、加权 Dijkstra/A*、贪心目标分配、三层锁、WebSocket 快照推送。
- 被追问“你具体负责什么”时，落到自己最有把握的 1–2 个模块/机制（如 Controller 调度 + common 公共库 + 分布式联调），不要空说“核心”。
- 不称“负责人/架构师”；4 人课程项目，统一说“核心开发/参与者”。

**核心机制**：

1. **一次 tick 五段**：ASSIGN_TARGET → PLAN_ROUTE →（可选监督优化）→ TICK_MOVE → REFRESH_ALL（Fanout）。
2. **路径规划**：枚举 BFS 档实际是 WEIGHTED_DIJKSTRA；ASTAR 档是加权 A*（gCost + 曼哈顿启发，四连通可采纳）；已探索代价 5、未探索 1；纯 BFS 只在单测做基线。
3. **目标分配**：<85% 逐格前沿贪心（路径长度 + 6×重合 + 20×贴边 − 4×连通块 − 2×路径未探索 − 4×深度）；≥85% 聚类收尾；同 tick `allocatedTargets` 去重。
4. **防冲突三层**：每车分布式锁 `SET NX`；位置预约锁 `pos:reserve:{x}:{y}` `SET NX EX 3`（连续失败 3 次转 BLOCKED）；`isOccupiedByOtherCar` 复查。
5. **密封区**：被障碍包裹、不可达的空格；探索率分母剔除，否则永远到不了 100%。
6. **实时推送**：Controller 发 `REFRESH_ALL`（Fanout `UpdateView`）→ Display 读 Redis 全量快照 → WebSocket 广播；不是轮询。
7. **存储**：Redis 是实时黑板；SQL Server 是可选持久化（用户/注册/日志/场次/统计，密码 jBCrypt）；核心仿真只依赖 Redis + RabbitMQ。

**关键数字（严格区分口径）**：

| 数字 | 性质 | 说法 |
|---|---|---|
| 3 车 30×30 约 3–5 分钟探索率 100% | 实测（小组联调） | 可以直接说，注明配置：3 车/30×30/BFS 档/500ms |
| 探索率 80% 多，>85% 自动切聚类 | 实测 | 可以说 |
| WebSocket 端到端 ≤200ms | 设计目标值 | 不要说成实测 benchmark |
| 地图初始化 <3s（30×30、5 车） | 设计目标值 | 同上 |
| 单次移动 <200ms | 设计目标值 | 同上 |
| 偶发单 tick ~800ms | 实测抖动 | 多车 + 高密度障碍；不影响正确性 |
| 3D Unity 视图最大 70×70 | 限制 | 100×100 时 2D 正常、3D 不支持 |
| “全程无碰撞、无重复分配” | 演示观察结论 | 由锁 + 预约 + 同 tick 去重保证，不是数学证明 |

**高频追问**：

1. 为什么用黑板架构？多智能体共享一张地图，需要公共状态板 + 独立知识源；解耦、可独立部署、易扩展。
2. 9 个 Maven 模块为什么简历写 7 个进程？common 是库、launcher 是可选启动器，不是进程。
3. 一次 tick 的完整数据流？按五段背。
4. 代码枚举叫 BFS/A*，为什么简历写 Dijkstra/A*？BFS 档实际是 WEIGHTED_DIJKSTRA，ASTAR 档是加权 A*；纯 BFS 只在单测。
5. A* 启发可采纳吗？四连通 + 曼哈顿距离，不会高估；八连通才要换切比雪夫。
6. 多车怎么防碰撞/防扎堆？目标侧同 tick 去重 + 重叠惩罚；移动侧三层锁。
7. Controller 怎么保证单实例？`SET NX EX 30`；没有心跳续期，只是防重复启动，不是高可用主备。
8. 为什么实时用 WebSocket 而不是轮询？推送、低延迟、职责单一；大地图整图推送会卡，是已知不足。
9. 项目有什么不足？课程项目/AI 辅助/非生产级；MOVING 异常未回写 READY；3D 70×70；配置错误提示不醒目；大地图快节拍卡顿；中间件短时不可用恢复不完善。
10. 是不是 AI 写的？坦诚 AI 辅助；架构和关键机制是小组定的，我负责的模块亲手调通，能用细节证明。

**风险与边界**：

- 不要把它说成生产系统、实习项目或高可用集群。
- “核心开发”必须能落到具体模块/机制，否则容易被追问穿。

## 8. 面试口径与红线（考前背这一页）

### 8.1 十条红线

1. **简历不改**：不新增项目、不升级头衔、不把“熟悉”说成“精通”。
2. **三个项目都是团队项目**：不说“独立完成”；统一说“核心开发/全程参与/负责某条线”。
3. **乡兴不称负责人**：团队负责人是李财源；我是核心开发/工程线。
4. **伊岐优选不是从零自研**：基于黑马点评二次开发 + 功能扩展 + 换名；重点讲改造和思考。
5. **变电站是课程项目**：4 人、3 学分、AI 辅助、非生产级；主动坦诚反而加分。
6. **AI 辅助不回避**：被问就承认；落点是“设计决策和整体理解是我的，AI 是编码提效”。
7. **数字带口径**：`≤200ms / <3s` 是设计目标；`3–5 分钟 100%` 是实测；`98% / <1.5s` 是项目自述；压测数字是笔记数据。
8. **不称“数字人/预训练/云原生集群”**：乡兴是 AI 向导 + 提示词 persona；不是数字人，不是预训练。
9. **不把了解说成精通**：Pixel Streaming/WebSocket/Niagara/MPC/3ds Max 按“团队技术栈/我参与集成/原理清楚”讲。
10. **不主动提未问及的弱项**：被问缺点时，用“具体不足 + 改进动作”，不要泛泛自我否定。

### 8.2 数字口径速查

| 说法 | 正确口径 |
|---|---|
| 变电站 3–5 分钟 100% | 实测：3 车/30×30/BFS 档/500ms，小组联调 |
| 变电站 WebSocket ≤200ms | 设计目标值，不是 benchmark |
| 变电站初始化 <3s、单次移动 <200ms | 设计目标值 |
| 变电站“全程无碰撞、无重复分配” | 演示观察结论 + 锁/预约/同 tick 去重保证 |
| 乡兴 AI `<1.5s / 98%` | 项目自述/自测指标，不是第三方压测 |
| 乡兴“网页在线进入 3D 展馆” | 文件确认的效果；具体技术路线按实际讲 |
| 伊岐秒杀 500ms→176ms | 项目笔记压测（本地环境） |
| 伊岐二级缓存 4.95×/1.63× | 项目笔记压测；说“笔记里的压测数据” |

### 8.3 被问不会/被质疑时

- **不会的八股**：“这个点我目前没有直接做过/记不太清，但我的理解是……如果现在让我做，我会先……再……。”
- **被质疑项目真实性**：“项目是真实做的，有代码/报告/证书；其中哪些是我主攻、哪些是团队协作，我可以分开讲，不夸大。”
- **被问 AI 辅助**：“确实大量用了 AI 辅助，这是事实；架构和关键取舍是小组定的，我负责的模块亲手调通，可以用细节证明。”
- **被问“是不是培训班/模板项目”**：“伊岐优选确实基于黑马点评，我没有把它包装成从零自研；我的价值在于改造了哪些点、为什么这么改、怎么验证。”

### 8.4 反问清单（5–6 个，按公司选）

1. 这个岗位入职后前 3–6 个月最重要的产出是什么？
2. 团队目前的技术栈和业务方向，新人会从哪类模块切入？
3. 团队对代码质量/测试/Code Review 的要求和流程是怎样的？
4. 这个岗位更看重后端深度、全栈能力，还是业务理解？
5. 团队的新人培养/导师机制是怎样的？
6. 如果我入职，您希望我优先补哪方面的能力？

> 避免：薪资、加班、转正比例等敏感问题（除非 HR 面主动提）。
