## 2. 版本A：1~2 分钟电梯版（可直接背）

"这是一个大创项目，叫『乡兴未来』，全称是基于 UE 蓝图和 C++ 的交互探索与实现。选题背景是红色文化和乡村振兴，原型选的是河北省阜平县骆驼湾村——这是 2012 年 12 月总书记踏雪走访、发出脱贫攻坚动员令的一个标志性村庄。

我们做了一件什么事呢？用 UE5 从零搭了一套数字孪生平台：最核心的成果是**两套高精度三维场景**——一套是总书记走访的重点房屋精细化场景，连房屋外观、院落、内饰、家具农具都做进去了，里面还配了一个红色文化虚拟展馆；另一套是整个骆驼湾村全域的 1:1 复刻场景。然后是**三端适配**，同一套工程打包出 PC 的 exe、Android 的 apk，以及支持 SteamVR 头显、六自由度的 VR 版本。

我是项目的核心开发，主攻 UE 交互系统和线上网站前后端：UE 里的蓝图/C++ 交互（自动门、答题机、电视机、展板、灯光）、网站的主页/留言板/下载中心/管理后台都是我参与做的，AI 向导和三端打包我也做过，建模是队友。这个项目拿了中国大学生计算机设计大赛全国三等奖、省赛一等奖，是国家级大创项目（结项良好），软件著作权申请中。"

## 3. 版本B：8~12 分钟详细版（分章节，可照念）

> 每章节标题后是"口语稿"，章节内【】里是给你自己的提示，不是念出来的内容。

### 0. 开篇：一句话定位 + 我为什么要讲这个项目

"我今天想用一个我全程参与的大创项目来讲我的能力，叫『乡兴未来』。一句话概括：**它是一个以 UE5 为引擎、以骆驼湾村为原型的数字孪生平台，两套高精度场景、PC/Android/VR 三端、再配一个线上网站，把数字孪生、VR、AI 导览和网页服务串成了一套体系。** 我选它讲，是因为它是从零到一、跨了引擎、AI、多端、Web 四个方向的项目，最能把我的动手能力和工程思维说清楚。"

### 1. 背景：为什么做这个项目

"这个项目的出发点不是纯炫技，是有一个真实的问题。我们观察到，现在很多红色文化、乡村文化还是靠展板、图片、静态实物来展示，形式单一、互动性弱、传播范围也有限，年轻人不太愿意看。而数字孪生和实时渲染技术成熟了，能不能用它把红色乡村'搬'到线上？

我们选的原型是河北省阜平县骆驼湾村。这个村庄有很强的代表性：2012 年 12 月 30 日总书记踏雪走访、发出了脱贫攻坚的动员令，它曾经是贫困发生率接近 70%、人均可支配收入只有 950 块的太行山深处山村，后来实现了整体脱贫，成了全国乡村振兴的一个典范。这样一个村子的红色历史和脱贫成就是很有传播价值的，但它缺少一个沉浸式、高互动、广覆盖的数字化展示手段。

所以我们就想做一件事：用数字技术把这段历史和村庄风貌永久保存下来，做成一站式的红色教育平台。它既是技术项目，也是服务思政教育、红色研学的一件事。这就是项目的立意。"

### 2. 核心成果：两套数字孪生场景 + 三端 + 网站

"整个项目的成果，我觉得可以分成三层来理解：**场景层、终端层、网站层**。

**第一层是场景，也是工作量最大的部分——两套 UE5 高精度场景。**
第一套是'重点房屋精细化场景'，对标总书记走访的那几栋房子。我们不是只做一个外观壳子，而是把房屋外观、院落布局、内饰、家具、农具，甚至人物、动物、车辆、植被这些细节都做进去了，里面还专门搭了一个**红色文化虚拟展馆**，展馆里有发展历程展板、历史影像墙、答题机、电视机和 AI 向导。
第二套是'骆驼湾村全域 1:1 复刻场景'，把整个村庄的布局、民居、道路、山地地形、植被，按实景数据一比一铺出来，你能在整个村子里自由走动，从'重点房屋'跳到'全村全局'。

模型怎么来的？我们是先做实地调研，收集走访路线、重点房屋结构、室内陈设、村庄布局这些素材，再基于实景数据建模。一号院、二号院、村会议室、民宿这些典型建筑，篮球场、公路、湖泊桥梁这些环境基建，都是这么搭出来的。

**第二层是三端适配。**
同一套工程，我们打包出 PC 的 LTW.exe、Android 的 LTW.apk，还有 VR 版本——连接 SteamVR 头显（比如 HTC Vive、Oculus Quest）会自动进入 VR 模式，走六自由度（6DoF），支持平滑移动和瞬移传送两种方式。这里有个点我觉得可以展开：三端共用一套核心玩法，靠的是在交互层做了统一，输入在 PC 上是键盘鼠标、手机上是虚拟摇杆、VR 上是手柄射线，但业务逻辑是同一套，这是跨端工程里比较吃经验的地方。

**第三层是线上网站。**
我们把这个项目配了一个线上宣传网站（域名 LuoTwoWan.cn），有主页、发展时间轴、虚拟展馆入口、功能介绍、下载中心、留言板和管理后台。特别说一下虚拟展馆入口：网页上点击就能加载进三维展馆，系统会自动识别设备类型，匹配 PC 或 Android 的操作方式，这样不用装客户端也能先体验。网站上还有下载中心，能按设备下对应的安装包；留言板要后台审核后才能公开，配套的管理后台能审核留言、看下载统计、更新内容。"

【提示：如果面试官问"网页在线跑 UE 展馆是怎么做的"，只说自己确定的部分；不确定是否用了 Pixel Streaming 就按第 4 节的坦诚话术收回来，别硬答。】

### 3. 我的角色（全项目 + 主攻 UE 交互与 Web 前后端，照此讲）

> 你的定位：**整个项目都有参与、非建模这块都算你的**；主攻是 **UE 交互系统** 和 **线上网站前后端（Web）**，AI 向导、三端打包、网页接入也都做过；建模（房屋/家具/贴图/光照）是队友主力。深度统一"上手做过、能讲原理、不深入"。

"我作为核心开发参与了整个项目，主要是在工程这条线。我最熟的是 **UE 的交互系统**——自动门、答题机、电视机、展板、灯光这些交互是我一个一个做出来的；其次是**线上网站的前后端**，主页、留言板、下载中心、管理后台这套我参与得比较深；AI 向导、三端打包、网页接入这些我也都做过。建模这条线（房屋家具贴图光照）主要是队友在做，我了解、但不深入。整体上我是能把引擎侧到 Web 侧这条链路串起来的人。"

> 被问"你最深哪块"：答 **UE 交互**（准备 1 个交互点的完整实现、能讲 3 层）；被问"Web 这块"：答网站前后端（主页/留言审核/下载统计/内容管理能讲出闭环）。AI 向导、打包、网页接入到"知道原理 + 做了什么"即可。

### 4. 亮点一：UE5 双数字孪生——"一个项目做两套场景"

"第一个亮点我想讲**双数字孪生**这件事。很多展示类项目做一张地图就够了，但我们做了两张，而且两张的'颗粒度'不一样：一张是'点'——把重点房屋做到家具、农具、室内陈设级别的精度，配上红色展馆；另一张是'面'——把整村全域一比一副刻。点面结合，既能把总书记走访的历史细节讲细，又能让人看到村庄整体面貌和脱贫前后的变化。

技术上为什么会遇到挑战？因为两套场景的工作量、加载策略和性能目标不一样。精细化场景吃模型精度和光照，全域场景吃地形和性能。我们在 UE5 里用蓝图和 C++ 搭交互（交互/UI/事件逻辑以蓝图为主，C++ 用在性能敏感、需封装复用或接外部接口的底层；具体模块我核对工程后展开），用材质、贴图、光照、动画去还原真实感，再用随机函数做了虚拟车流、用 NPC 的行走/交谈/劳作让村子'活'起来，天气系统支持风雨天、水雾天、昼夜交替和云的移动。最终同一套工程要在 PC、Android、VR 三端都跑起来，这个'精度和性能之间做平衡'的过程，是我觉得最有收获的地方。"

### 5. 亮点二：AI 向导——DeepSeek API 的垂类应用

"第二个亮点是 **AI 向导，这是整个项目里我最想展开讲的一块**，因为它把'大模型'落地到了具体场景里。

做法是：在展馆里放一个 AI 向导（文件里叫'智能村民'），用户按 Tab 键唤醒对话框、输入问题，后端接 **DeepSeek API** 实时响应，支持**多轮追问**。为了让它更贴合场景，我们在提示词里做了**身份设定——把 AI 设定成'村民'这个人设**，所以它回答的语气是贴合村民身份的，而且支持**方言和普通话自动切换**。这样它不只是个冷冰冰的问答机器人，而是像一个带你逛村子的老乡。

两个指标：使用说明书里标注对话**延迟小于 1.5 秒、数据准确率 98%**。这里我主动说明一下：这两个数字是我们自己在软件使用说明里标注的项目口径，不是第三方压测出来的，但它是我们调下来实际能达到的水平。

这块最能体现我哪方面能力？一方面是把大模型 API 包装成一个有'人设'、有多轮上下文的对话系统；另一方面是延迟控制——在三维场景里用户对响应是敏感的，我们把请求做成异步、精简系统提示词、限制回答长度、UI 先给状态反馈，让问一句不会卡住漫游（延迟自测压到 1.5 秒内）。"

【提示：这里特别要讲清是"提示词做 persona"，不是"垂类身份预训练"。如果面试官问"是不是微调/预训练了模型"，直接说："没有做模型训练，是通过提示词工程设计人设和语境，加上对返回结果的约束，成本低、可控、也够用。"】

### 6. 亮点三：三端 + VR + 网站，成体系而不是单点

"第三个亮点是**体系化**。很多学生项目的问题是'只有一个 demo'，我们把它做成了可以真正用起来的一套东西：

- 交互功能是一整套的：WASD 漫游 + 鼠标环视、ESC/P 设置面板（分辨率、声音、移速、全屏）、电视机播放纪录片、H/F 打开关闭展板、G 键灯光、E 键答题机（答错标红、答对标绿）、数字键传送、靠近自动开门的自动门、天气变化。
- 终端是全覆盖的：PC / Android / VR 三端可下载可运行，VR 走 6DoF。
- 配套是闭环的：线上网站负责宣传、在线体验和下载分发，留言板 + 管理后台负责收集反馈。

一句话：它是一套'展示 + 体验 + 运营'的完整平台，不是一张孤立的地图。这个'把东西做成体系'的意识，是我在这个项目里特意去培养的。"

### 7. 量化成果与获奖

"最后讲结果。核心成果是三样：**两套高精度三维场景 + 三端可运行安装包 + 一个线上网站**，实现了沉浸式漫游、AI 导览、答题互动、天气模拟这些功能。

奖项和背书我如实说：这个项目参加了**学科竞赛并获奖（获奖证书我这边留着、可备查）**，作为**大创项目顺利结题**（立项级别以立项文件为准），软件著作权正在申请中。另外可以补一句：这是我们 3 人团队、200 元经费做的项目，经费全部花在调研差旅上，其他全靠自己一行行写、一版版打包，所以它不是我简历里最大规模的项目，但绝对是我投入最深、最完整的一个。"

【提示：获奖名次务必对着你手里的证书说，别把"全国三等奖/省赛一等奖"讲成自己没把握的更高级别。】

### 8. 坦诚不足（主动讲，反而加分）

"这个项目我不回避它的短板，主动说三点：

1. **场景精度有优化空间**：受设备和时间限制，远景模型、植被密度、光影效果还能做得更好，我们标注的 PC 最低配置是 i5-8400 / GTX 1060，考虑到性能做了取舍。
2. **VR 端交互还能再扩展**：目前 VR 端以漫游和讲解为主，未来可以做手势交互、多人同步参观这类更沉浸的玩法。
3. **网站高并发能力有限**：现在满足展示和个人使用没问题，真要大规模推广，服务器性能和加载速度要再升级。

项目过程中也踩过不少坑：从打包报错、VR 适配失败，到最终两套地图上线、三端跑通、网站开通，是反复攻关过来的。这些'难度'恰恰是我认为在面试里最值得讲、也最真实的部分。"

## 4. 收尾：被问"是不是夸大/套模板"时，怎么坦诚应对

面试官如果直接问"你简历里写 Pixel Streaming、Niagara、MPC、数字人、预训练，这些你真的都会吗？"，或者旁敲侧击"项目听起来像是套了个模板"，建议这样接（可按你的实际情况删改）：

> "谢谢您问到这个，我正面回应。第一，项目本身是真的：骆驼湾村的原型、两套场景、三端打包、网站，这些都有结题报告和软件使用说明书可以佐证，不是我编的。

> 第二，我确实要坦白口径。简历里有些技术名词，比如 Pixel Streaming、Niagara、MPC、3ds Max 这些，写的是**团队技术栈**，而不是每一项我都深度自研。我个人真正跟得深、能跟您聊到底层的是这几块：**UE5 蓝图/C++ 的交互系统、AI 向导的 DeepSeek API 集成和提示词设计、以及网站的前后端**。像 Pixel Streaming 这类我承认是接触和集成层面，不是我自己造轮子，所以我也不愿意在您面前夸大。

> 第三，关于'数字人'这个词，我得修正一下：我们做的是**基于 DeepSeek 的 AI 问答向导（智能村民）**，是文本对话 + 身份设定的人设，不是有形象、有动捕的那种虚拟数字人，更没做什么'垂类身份预训练'——那是队友简历里写得偏大的一处，我在这边跟您说清楚准确的做法。

> 所以如果您是想验证我是不是真做过，我可以顺着任何一条我负责的线往下讲：比如 AI 向导的多轮对话怎么维护上下文、村民人设提示词怎么设计、延迟是怎么压到 1.5 秒以内的；或者答题机、电视机这些交互在蓝图里是怎么组织的。我宁可讲清楚一个窄但真实的东西，也不希望靠堆名词过关。"

这段的核心心法是：**主动承认"哪些名词是团队的、不是我的"，把谈话拉回到"你能讲到底层"的那块真实内容上。** 这比被追问穿帮后再解释，可信度高一档。
