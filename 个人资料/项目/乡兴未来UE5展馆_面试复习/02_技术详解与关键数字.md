## 0. 一句话定位

以 UE5 为引擎、以河北省阜平县骆驼湾村为原型的红色乡村数字孪生平台：两套高精度场景 + 三端（PC / Android / VR）+ 线上网站，融合数字孪生、VR、人机交互、AI 导览、网页服务，服务于红色研学与乡村振兴宣传。

## 2. UE5 数字孪生：双场景建模思路

**为什么分两套而不是一套做全**：全场景都做到"能进屋内看细节"的精度，算力和工作量扛不住；拆成"重点局部精细化 + 全域大体复刻"两层，是最经济的取舍。

- **场景① 总书记走访重点房屋精细化场景**：房屋外观、院落、内饰、家具、农具、人物、动物、车辆、植被等全细节 + 红色文化虚拟展馆。对应"沉浸游、看细节、做展板/答题/电视机等交互"。
- **场景② 骆驼湾村全域 1:1 复刻场景**：村庄布局、民居、道路、山地地形、植被。对应"从宏观了解村落全貌与地理环境"。
- 典型建筑：一号院、二号院、村会议室、民宿；环境基建：篮球场、公路、湖泊桥梁、村庄新貌。
- 本项目里的"数字孪生" = 三维建模 + 材质/贴图/光照/动画，把真实村落地形与重点房屋在引擎里 1:1 还原，再叠加交互，形成可漫游、可交互的数字空间。

## 3. 蓝图 vs C++ 分工

项目标题本身就是"基于 UE 蓝图/C++"，两份文件都确认两者都被使用。建议口径（诚实、可恢复）：

- **蓝图（Blueprint）为主**：交互逻辑（碰撞触发、按键响应、UI 面板、答题对错标色、灯光/电视/传送等）用蓝图事件图 + 时间线/插值实现，开发快、好维护。
- **C++ 用于更底层 / 性能敏感或需要严谨逻辑的部分**，例如高频调用、封装复用、与外部 HTTP 接口对接等场景。具体落在哪几个模块，面试前对照工程核实清楚，不要张口说"全用 C++ 写了状态机"。

> 口径提醒：队友简历里"C++ 构建交互状态机模型"不是文件原文口径。如被追问，按"蓝图状态逻辑为主 + 关键底层用 C++"讲，别照抄夸大说法。

## 4. 交互功能清单（按对象归类 + 怎么实现/为什么）

以 Windows 端为例，工程实际落地了以下交互。"典型实现"栏是 UE5 通用做法，供口头讲清原理，具体以你们工程为准。

| 功能 | 触发/操作 | 怎么实现 / 为什么 |
|---|---|---|
| 自由漫游 | WASD / 方向键移动 + 鼠标环视 | 角色控制器 + 摄像机，实现第一/第三人称环视浏览 |
| 设置面板 | ESC / P 打开 | 分辨率、声音、移动速度、全屏开关，读写玩家偏好 |
| 电视机播放 | 数字键 1 播放 / 2 暂停 | 播放脱贫攻坚纪录片与总书记走访影像，视频材质贴到屏幕 |
| 展板阅读 | H 打开图文 / F 关闭 | 靠近展板触发 UI，弹图文讲解 |
| 灯光开关 | G 键开关 | 切换展馆灯光可见性/亮度 |
| 答题机 | E 键交互 | 答对标绿、答错标红；进出答题界面时鼠标自动显示/隐藏 |
| 展台传送 | 数字键 1/2/3/4 | 一键传送到对应展台，省长距离走位、优化浏览动线 |
| 自动门 | 靠近自动开合 | 碰撞触发 + 时间线/插值做门的旋转，离开后关闭 |
| AI 向导 | Tab 唤醒 | 输入问题，走 DeepSeek API，见第 6 节 |
| 虚拟车流 | 自动运行 | 随机函数模拟车辆行驶，让路面"活"起来 |
| NPC | 自动/靠近 | 行走、交谈、劳作，营造村落生活气息 |
| 天气变化 | 自动/时段 | 风雨天、水雾天、昼夜交替、云的移动 |

设计目的：这些交互不是堆功能，而是服务"红色研学 + 沉浸体验"——电视机和展板承载内容讲解，答题机承载互动考核，传送和自动门优化动线，天气/车流/NPC 提升沉浸感。

## 5. 三端适配差异

"一套工程适配三端"是文件确认的成果，差异主要在输入方式：

- **PC（LTW.exe）**：键鼠，WASD/方向键 + 鼠标环视，功能最全（上文清单基本以 Windows 端为准）。
- **Android（LTW.apk）**：触屏 + 虚拟摇杆，做操作映射与触屏 UI 适配，保证骁龙 845 / 4GB 等配置可跑。
- **VR（SteamVR 头显，如 HTC Vive / Oculus Quest）**：六自由度（6DoF）手柄交互，支撑"平滑移动 + 瞬移传送"两种方式，减少晕动；连接 VR 设备时自动进入 VR 模式。

**为什么同一套核心能三端复用**：UE5 本身跨平台，通过输入抽象（Player Controller / Input）+ 平台差异化配置（按键绑定、触屏 UI 不同）覆盖三端；额外要做的是各端打包配置、输入映射与性能裁剪（远景模型、植被密度在移动端降档）。

## 6. AI 向导（简历最亮的点，务必按文件口径讲）

- **实现**：基于 DeepSeek API 实时响应，支持多轮追问，HTTP 请求承载对话。
- **身份设定**：通过"村民身份提示词"让 AI 以村民口吻回答，支持方言与普通话自动切换——这是 prompt 层面的 persona（人设），**不是"垂类身份预训练"**，别说成重新训练过模型。
- **触发方式**：Tab 键唤醒对话框，输入问题。
- **性能指标（文件原文口径）**：对话延迟 < 1.5 秒，数据准确率 98%。这两个数字是使用说明书写明的**项目自述指标**，不是第三方压测，主动说清"这是我们自己测的目标值"反而显诚实。

**为什么用它**：静态导览是"点哪个讲哪个"，AI 向导解决"游客想问的没准备好"的兜底；村民人设贴合骆驼湾村叙事，增强沉浸感。

## 7. 网站全栈（已部署 http://LuoTwoWan.cn）

**前端（面向访客）**：主页、发展时间轴、虚拟展馆入口（网页可加载进入、系统自动识别设备类型）、功能介绍（图文/动图/短视频 + 点赞评论）、下载中心（Win / Android / VR 安装包）、留言板（后台审核后可见）。

**后端（管理后台）三个核心模块**：留言审核、下载统计、内容更新/管理接口。

**为什么做网站**：VR/PC/App 都需下载安装，网站把"宣传 + 在线预览 + 下载入口"串起来，是项目的门面和落地闭环。

这是简历里最容易被追问、也最容易翻车的部分，按下面区分讲：

- **文件确认的**：使用说明书确有"网页点击虚拟展馆 → 加载进入 → 系统自动识别设备类型"的描写，可作为"网页能在线运行 3D 展馆"的依据。

## 10. 已知不足 / 改进方向（被问"有什么缺点"直接答）

1. 部分场景细节与模型精度仍有优化空间（远景模型、植被密度、光影效果）。
2. VR 端交互可继续扩展（目前以漫游与讲解为主，未来可加手势交互、多人同步参观）。
3. 网站高并发承载能力有待加强（当前满足展示与个人使用，大规模推广需提升服务器性能与加载速度）。
