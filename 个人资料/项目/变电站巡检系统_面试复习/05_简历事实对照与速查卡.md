## 二、口径三分：实测值 / 设计目标值 / 需收敛措辞

**1. 实测值（可以直接说，且要会报出处与方法）**

- 探索率 100%：30×30、3 车、BFS、500ms 节拍，约 3~5 分钟（personA 联调实测）。
- 探索率可达 80% 多、超 85% 后 TargetPlanner 自动切聚类策略（personC 实测）。
- 实测抖动：多车 + 高密度障碍时偶发单 tick 延迟到约 800ms（MQ + 多进程调度开销，判定不影响正确性）。
- 3D Unity 视图最大 70×70（100×100 时 3D 不支持、2D 正常）。

**2. 设计目标值 / 验收指标（说"目标"或"验收指标"，别说"实测 ≤"）**

- WebSocket 端到端 ≤200ms —— 目标值。
- 地图初始化 <3 秒（30×30、5 车）—— 目标值。
- 单次移动 <200ms —— 目标值。
- 节拍 500ms（可调 100~2000ms）—— 默认配置，非性能承诺。

**3. 偏强、需收敛的措辞**

- **"全程无碰撞、无重复分配"**：改为"演示全程未观察到碰撞或重复分配（由分布式锁 + 位置预约锁 + 同 tick 去重保证）"。把绝对结论降级为有机制支撑的观察结论。
- **"WebSocket 端到端延迟 ≤200ms"**：这是设计目标值不是 benchmark。被追问实测时坦承"是目标值，实测有 ~800ms 抖动场景"。
- **"核心开发"**：必须能落到具体模块（见四人分工），否则是空话。
- **"完成 4 人 4 机联调"**：语意可保留"完成"，但要说明是课程/教学环境的联调，不是生产级；否则面试官可能追问监控、容灾、发布等超出课程范围的问题。

### 2. 核心概念口诀

- **架构一句话**：一黑板、一总线、一调度、七知识源。Redis 是真相源，RabbitMQ 是邮路，Controller 是唯一指挥，7 个模块是只会读写黑板/收发消息的知识源。
- **一个 tick 五段**：ASSIGN_TARGET（分配目标）→ PLAN_ROUTE（规划路径）→（可选监督优化）→ TICK_MOVE（移动）→ REFRESH_ALL（Fanout 刷屏）。
- **路径"喜新厌旧"**：已探索代价 5、未探索代价 1——探过的路变贵，自然往没探过的区域钻。
- **两算法换皮**：枚举叫 BFS 其实是 Dijkstra，叫 ASTAR 其实是加权 A*。
- **分配两刀切**：85% 前逐格抠前沿，85% 后聚类收尾（因为快满了，散点贪心会乱跑）。
- **防撞三保险**：每车锁串行 → 位置预约锁防同格 → isOccupiedByOtherCar 再查一遍。
- **module 数对不上**：9 = 7 进程 + 1 common 库 + 1 launcher 可选启动器，common 不是进程。

### 3. 高频考点 TOP10

1. 为什么选黑板架构，而不是微服务/事件驱动？（解耦到"零直接调用"、Redis 单一真相源、加新知识源只挂总线、Controller 统一调度）
2. Maven 9 个模块 vs 7 个进程怎么解释？（common 库 + launcher 可选）
3. Redis 怎么当"黑板"？键怎么设计？（mapView/mapBlock/mapSealed 位图、mapHeat、TaskConfig、Car{id}:*、explorationEvents、controller:instance、pos:reserve:*）
4. "加权 Dijkstra/A*"加权在哪？启发函数可采纳吗？（未探索代价低；曼哈顿距离在四连通网格可采纳）
5. 目标分配为什么 85% 分两阶段？打分公式每一项的动机？（贴边惩罚、重合惩罚、连通块奖励、深度奖励）
6. 多车怎么防碰撞、防扎堆？（三层锁 + 重叠惩罚 + 同 tick allocatedTargets 去重）
7. 讲一遍一次 tick 的完整消息流？（IDLE 车 → … → REFRESH_ALL → WebSocket broadcast）
8. Controller 怎么保证分布式单实例？（SET NX EX 30 的 Redis 锁）
9. 为什么实时走 WebSocket 推送而不是浏览器轮询？每帧发什么数据？（REFRESH_ALL Fanout → Display 读全量快照 → 广播；帧含 tick/探索率/车数组/三张位图）
10. 项目有什么不足？（MoveExecutor MOVING 心跳异常未回写 READY、3D 仅 70×70、infra.local.json 配错提示不醒目、大地图快节拍整图传输卡顿、中间件短时不可用恢复不完善）

## 四、简历措辞优化建议（不造假前提下的更专业写法）

1. **把"核心开发"落地为模块 + 职责**。示例："负责 controller 调度核心与 common 公共库（Redis 黑板封装、RabbitMQ 总线、分布式联调）"。比"核心开发"可验证，也直接击碎"你具体做啥"的追问。
2. **把绝对结论改为"机制 + 观察"**。原句"全程无碰撞、无重复分配"改为："演示全程未观察到碰撞或重复分配，通过分布式锁 + 位置预约锁 + 同 tick 目标去重保障"。既诚实又显出你理解保障来自哪里。
3. **给目标值加标签**。把"WebSocket 端到端延迟 ≤200ms""初始化 <3 秒"写成"设计目标 / 验收指标（WebSocket ≤200ms、初始化 <3s）"，避免被当 benchmark 追问后露怯。
4. **技术栈标注依赖层级**。"SQL Server（可选持久化，核心仿真仅依赖 Redis + RabbitMQ）"——既能展示你知道主次，也防止面试官就 SQL 深挖时失分。
5. **给项目一句诚实的定位前缀**。"课程项目（软件工程 + 软件体系结构，4 人小组，AI 辅助开发）"——把课程、规模、AI 辅助放在台面上，反而让后面所有技术点显得真实可信；被问"是不是 AI 写的"时坦承并补充"我负责设计与联调的部分"。
6. **给 Unity 加版本限定**。"Canvas/Unity 双视图（3D 视图支持至 70×70 地图）"，主动交代边界，避免 100×100 追问被抓。
