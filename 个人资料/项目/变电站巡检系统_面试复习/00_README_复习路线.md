## 建议复习顺序（共约 1.5~2 小时）

1. **先读 01 讲解稿**（30 分钟）：把"一句话定位 → 背景 → 架构 → 一次 tick → 我的角色 → 亮点 → 成果 → 坦诚不足"这条线在脑子里串起来，能对着镜子完整讲一遍。
2. **再读 05 速查卡**（15 分钟）：背关键数字口诀和"三句诚实话"，把简历每句话的口径对一遍。
3. **精读 03 + 04 问答**（40 分钟）：每题先自己答，再看答案；重点题（标了"必问"的）要能 30~60 秒口头复述。
4. **细节查 02**（15 分钟）：对某个机制记不清时，翻事实底稿定位到具体数字/模块。
5. **考前 5 分钟**：只看 05 的"一页速查卡"和 01 的"电梯版"。

## 全包一致的关键口径（面试前必须记住）

1. **定位**：这是课程作业项目（软件工程 + 软件体系结构两门课、3 学分、4 人小组），**大量借助 AI 辅助开发，不是生产系统**。被问"是不是 AI 写的"要坦诚承认，并立刻转到"设计决策是我做的、我能讲清为什么"。
2. **模块数**：简历写「7 个进程」是对的，但要能背出 **9 个 Maven 模块 = 7 个独立进程 + common(公共库) + launcher(可选一键启动器)**。
3. **三类数字，三种口径**（千万别混）：
   - **实测**：3 车 30×30 地图约 3~5 分钟探索率到 100%；探索率能到 80% 多/超 85%。
   - **设计目标值**：WebSocket 端到端 ≤200ms、地图初始化 <3s、单次移动 <200ms（**不是 benchmark，别硬说成实测**）。
   - **观察结论 + 机制保证**：全程无碰撞、无重复分配（由分布式锁 + 位置预约锁 + 同 tick 去重保证）。
4. **最容易问穿的坑**：代码枚举叫 BFS / ASTAR，但**实际实现是加权 Dijkstra / 加权 A***（BFS 档 = WEIGHTED_DIJKSTRA，ASTAR 档 = WEIGHTED_ASTAR）。这句要主动讲清楚。
5. **诚实三件套**：课程项目 / AI 辅助 / 非生产级。被问缺点时"先承认 + 给改进思路"，一条都别硬辩。

## 你的角色定位（已定稿）

**整个项目都算你做的、各模块都参与过——不框死在某个模块，而是对整个系统的架构、数据流、关键算法吃得比较透；深度"都上手做过、能讲原理、不钻底层"。**

讲的时候照 `01_项目讲解稿.md` 第 5 节那段说：「我作为核心开发全程参与，从调度器 controller、规划侧、小车执行端到前端 display 都做过、都能讲清角色和协作；理解最透的是 500ms 节拍调度、加权 Dijkstra/A*、贪心目标分配、三层锁防冲突、WebSocket 快照推送，能把整条链路串起来讲。」再补一条你有把握的落地细节（如"位置预约锁连续失败 3 次切 BLOCKED"）即可。

> 参考（四人分工，面试不必背名字，心里有数即可）：PersonA=common+controller、PersonB=car+认证、PersonC=规划模块、PersonD=display+launcher。

## 已知不足（被问"项目有什么问题"时直接讲，别再等被问）

1. 课程项目、AI 辅助、非生产级。
2. `MoveExecutor` 写 MOVING 心跳后异常退出，未显式回写 READY，状态可能短暂卡在 MOVING。
3. 3D Unity 视图最大只支持 70×70 地图（100×100 时 2D 正常、3D 不支持）。
4. `infra.local.json` 配置错误时，Controller 长时间等不到 TASK_READY，报错提示不够醒目。
5. 大地图 + 快节拍时每拍推整图，前端会卡。
6. 中间件（Redis/RabbitMQ）短暂不可用时的恢复不够完善。
